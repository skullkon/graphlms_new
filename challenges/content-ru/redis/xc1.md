На этом этапе вы расширите команду `INFO`, добавив значения `master_replid` и `master_repl_offset`.

### Идентификатор и смещение репликации

Каждый ведущий сервер Redis хранит две важные характеристики репликации: **идентификатор репликации** и **смещение репликации**.

Идентификатор репликации — длинная псевдослучайная строка. Он обозначает текущую историю набора данных ведущего. При первом запуске или перезапуске ведущий сбрасывает свой идентификатор.

Смещение репликации отслеживает количество байтов команд, переданных ведущим репликам. Это значение используется для обновления состояния реплик с учётом изменений данных. При запуске ведущего, пока реплики ещё не подключились, смещение равно `0`.

На этом этапе вы инициализируете идентификатор и смещение репликации ведущего сервера:

- Идентификатор может быть любой псевдослучайной буквенно-цифровой строкой длиной `40` символов.
  - В этом задании не обязательно генерировать случайную строку: можно задать её прямо в коде.
  - Например, можно использовать `8371b4fb1155b71f4a04d3e1bc3e18c4a990aeeb`.
- Смещение должно равняться `0`.

Команда `INFO` должна возвращать эти значения под ключами `master_replid` и `master_repl_offset` соответственно.

### Тесты

Тестирующая программа запустит вашу программу так:

```
./your_program.sh
```

Затем отправит серверу `INFO` с параметром `replication`.

```bash
$ redis-cli INFO replication
```

Программа должна ответить [объёмной строкой](https://redis.io/docs/latest/develop/reference/protocol-spec/#bulk-strings), каждая строка которой — пара «ключ — значение», разделённая двоеточием (`:`). Тест проверит пары:

- `role`: `master`
- `master_replid`: буквенно-цифровая строка из 40 символов.
- `master_repl_offset`: `0`

### Примечания

- Код должен проходить предыдущие тесты, то есть по-прежнему возвращать правильное значение `role`.
