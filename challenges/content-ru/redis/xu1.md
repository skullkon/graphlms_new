На этом этапе вы добавите поддержку `$` в качестве начального идентификатора при блокирующем чтении `XREAD`.

### Значение `$` как идентификатора записи

Если идентификатор равен `$`, `XREAD` возвращает только новые записи, добавленные после отправки команды. Это аналогично передаче максимального идентификатора, который сейчас есть в потоке.

Предположим, есть два отдельных клиента. Первый отправляет блокирующую `XREAD` со временем ожидания `1000` и идентификатором `$`:

```bash
$ redis-cli XREAD BLOCK 1000 streams some_key $
```

Затем второй клиент добавляет запись в поток `some_key`.

```bash
$ other-redis-cli XADD some_key 1526985054079-0 temperature 37 humidity 94
"1526985054079-0"
```

Как и на предыдущих этапах, если команда отправлена в течение `1000` миллисекунд, первый клиент разблокируется и получит новую запись:

```bash
1) 1) "some_key"
   2) 1) 1) 1526985054079-0
         2) 1) temperature
            2) 37
            3) humidity
            4) 94
```

Иначе ответом будет [нулевой массив](https://redis.io/docs/latest/develop/reference/protocol-spec/#null-arrays).

```bash
(nil)
```

### Тесты

Тестирующая программа запустит вашу программу так:

```bash
$ ./your_program.sh
```

Затем добавит запись в поток.

```bash
$ redis-cli XADD stream_key 0-1 temperature 96
```

После этого отправит серверу `XREAD` с `BLOCK`, временем `0` и идентификатором `$`.

```bash
$ redis-cli XREAD BLOCK 0 streams stream_key $
```

Из другого экземпляра redis-cli тест добавит ещё одну запись через `500` миллисекунд.

```bash
$ redis-cli XADD stream_key 0-2 temperature 95
```

Сервер должен вернуть следующий массив RESP:

```json
[
  [
    "stream_key",
    [
      [
        "0-2",
        [
          "temperature",
          "95"
        ]
      ]
    ]
  ]
]
```

Затем тест отправит ещё одну `XREAD` с `BLOCK`, но на этот раз подождёт `1000` миллисекунд перед проверкой ответа сервера.

```bash
$ redis-cli XREAD BLOCK 1000 streams stream_key $
```

Сервер должен ответить нулевым массивом (`*-1\r\n`).
