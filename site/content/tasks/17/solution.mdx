## Идея решения

Общая горутина ждёт таймер, передаёт одно разрешение через
небуферизованный `gate` и только после передачи запускает новый отсчёт.

## Эталон

```go
package solution

import "time"

// LeakyBucket — ограничитель по алгоритму leaky bucket.
//
// Внутренний цикл выдаёт разрешение через gate, затем заново отсчитывает
// interval. Простой не накапливает разрешения. Acquire ждёт разрешение.
type LeakyBucket struct {
	gate chan struct{}
	stop chan struct{}
}

// NewLeakyBucket создаёт ведро, пропускающее 1 запрос раз в interval.
func NewLeakyBucket(interval time.Duration) *LeakyBucket {
	lb := &LeakyBucket{
		gate: make(chan struct{}),
		stop: make(chan struct{}),
	}
	go lb.run(interval)
	return lb
}

func (lb *LeakyBucket) run(interval time.Duration) {
	timer := time.NewTimer(interval)
	defer timer.Stop()
	for {
		select {
		case <-lb.stop:
			return
		case <-timer.C:
			// Выпускаем одного ожидающего, если он есть.
			select {
			case lb.gate <- struct{}{}:
				timer.Reset(interval)
			case <-lb.stop:
				return
			}
		}
	}
}

// Acquire блокирует вызывающую горутину до её очереди.
func (lb *LeakyBucket) Acquire() {
	<-lb.gate
}

// Stop останавливает внутренний таймер.
func (lb *LeakyBucket) Stop() {
	close(lb.stop)
}
```

## Почему это работает

После простоя в отправке может ждать одно разрешение, но следующий интервал
начинается только после его получения. Поэтому простой не приводит к двум
разрешениям подряд из-за накопленного тика. Ожидание есть и на таймере, и на
отправке; оба `select` слушают `stop`.

`Stop` прекращает фоновую выдачу. Он не ждёт её выхода и не разблокирует
`Acquire`: этот метод читает только `gate`. По контракту сначала дождитесь
всех `Acquire`, затем единожды вызывайте `Stop`; новых вызовов после остановки
быть не должно. Для отменяемого API нужен `Acquire(ctx)` с `select` по контексту
и каналу остановки, а также возвращаемой ошибкой.

При непрерывном спросе первый допуск происходит примерно через `interval`,
а N-й — не раньше N интервалов от запуска таймера. Планирование может
задержать возврат самого `Acquire`; это модель интервала между разрешениями,
а не гарантия времени исполнения кода вызывающего. Строгого FIFO или
ограниченного времени ожидания конкретной горутины спецификация не обещает.

Таймер один, но память всех ожидающих горутин растёт с числом вызовов.
`interval` должен быть положительным. См. [каналы](/book/channels).
