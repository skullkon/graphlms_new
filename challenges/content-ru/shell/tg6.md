На этом этапе вы реализуете поддержку двойных кавычек.

### Двойные кавычки

В синтаксисе оболочки большинство символов внутри [двойных кавычек](https://www.gnu.org/software/bash/manual/bash.html#Double-Quotes) (`"`) трактуются буквально. Однако двойные кавычки допускают интерпретацию некоторых специальных символов (например, `$` для переменных и `\` для экранирования). Эти исключения мы рассмотрим на следующих этапах.

На этом этапе при разборе двойных кавычек оболочка должна применять следующие правила:

- Последовательные пробельные символы (пробелы, табуляции) должны сохраняться.
- Символы, обычно служащие разделителями или специальными символами, внутри двойных кавычек теряют специальное значение и трактуются буквально.
- Строки в двойных кавычках, расположенные рядом, объединяются в один аргумент.
    - Строки в кавычках и без кавычек, расположенные рядом, также объединяются.

Например:

```bash
$ echo "hello    world"
hello    world         # Multiple spaces preserved

$ echo "hello""world"
helloworld             # Quoted strings next to each other are concatenated.

$ echo "hello"world
helloworld             # Quoted and unquoted strings next to each other are concatenated.

$ echo "hello" "world"
hello world            # Separate arguments

$ echo "shell's test"
shell's test           # Single quotes inside are literal
```


### Проверки

Тестирующая система запустит вашу программу следующим образом:

```bash
./your_program.sh
```

Затем система отправит оболочке последовательность команд `echo`:

```bash
$ echo "quz  hello"  "bar"
quz  hello bar
$ echo "bar"  "shell's"  "foo"
bar shell's foo
$
```

Тестирующая система проверит, правильно ли команда `echo` выводит текст в кавычках.

Далее тестирующая система отправит команду `cat`, в которой имя файла заключено в двойные кавычки:

```bash
$ cat "/tmp/file name" "/tmp/'file name' with spaces"
content1 content2
```

Тестирующая система проверит, правильно ли команда `cat` выводит содержимое файла.
