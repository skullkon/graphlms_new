На этом этапе вы добавите поддержку обработки ошибок времени выполнения при обращении к ещё не объявленным переменным.

### Ссылка на книгу

Код для этого этапа реализован в [разделе 8.2: Глобальные переменные](https://craftinginterpreters.com/statements-and-state.html#global-variables).

### Проверки

Тестирующая система выполнит серию проверок с файлами `test.lox`, обращающимися к ещё не объявленным переменным.

Например, если `test.lox` содержит следующее

```
print a;
```

Тестирующая система запустит вашу программу следующим образом:

```
$ ./your_program.sh run test.lox
Undefined variable 'a'.
[line 1]
```

Тестирующая система выполнит несколько таких проверок со случайными выражениями, например:

Тестовый случай 1:

Входные данные:

```
print 22;
print x;
```

Ожидаемый вывод:

```
22
Undefined variable 'x'.
[line 2]
```

Тестовый случай 2:

Входные данные:

```
var baz = 96;
print hello;
```

Ожидаемый вывод:

```
Undefined variable 'hello'.
[line 2]
```

Тестовый случай 3:

Входные данные:

```
var hello = 85;
var result = (hello + bar) / world;
print result;
```

Ожидаемый вывод:

```
Undefined variable 'bar'.
[line 2]
```

Тестовый случай 4:

Входные данные:

```
var quz = 20;
var world = 51;
var hello = 56;
print quz + world + he
```

Ожидаемый вывод:

```
Undefined variable 'he'.
[line 4]
```

Тестирующая система проверит, что код завершения равен 70, что означает ошибку времени выполнения. Обратите внимание: он отличается от ожидаемого кода завершения при синтаксической ошибке — 65.

### Примечания

- Этот формат вывода соответствует спецификации в [репозитории книги](https://github.com/munificent/craftinginterpreters/blob/01e6f5b8f3e5dfa65674c2f9cf4700d73ab41cf8/test/variable/in_nested_block.lox)
- Сообщения об ошибках следует выводить в `stderr`, а не в `stdout`.
- На этом этапе тестирующая система не проверяет точный текст ошибки, а только завершение программы с кодом 70.
