# Учебный цикл System Design

Пользователь одобрил все семь направлений улучшения. Сохраняем текущие главы, адреса и прогресс; добавляем практические инструменты в существующий курс.

1. Каждая из 16 глав получает самостоятельный сценарий с объяснением выбора, постепенными подсказками, проверяемыми ответами и разбором после попытки. Проверка сценария не равна оценке архитектуры.
2. Сценарии проверяют состояние после отказа, потерянного ответа, гонки или изменённого условия. Существующие примеры в тексте остаются разобранными примерами.
3. Сквозной Клуб развивается в 16 этапов. Сохраняются версии решений; экспорт содержит историю и критерии самопроверки.
4. Структурированный разбор архитектуры проверяет явные несовместимые требования/механизмы. Открытые ответы оцениваются по рубрике человеком; автомат не угадывает их качество по ключевым словам.
5. Пошаговые модели показывают гонку последнего места, потерянный ответ и отставшую реплику. Перед запуском ученик записывает прогноз; шаги и сброс доступны явно.
6. Повторение использует завершённые сценарии и интервалы; интервью имеет задачу, этапы, изменённое условие и самооценку. Никаких гарантий найма.
7. Пилот: сценарий с реальными новичками, добровольный локальный сбор наблюдений, экспорт. Нет выдуманных участников и результатов. Техническая редактура и проверки выполняются агентами; человеческий пилот ожидает участников.

Хранение: существующие loadCode/saveCode в области system-design; новые префиксы ключей, проверка формы JSON, сообщение об ошибке сохранения. Старые заметки не заменяются. Личные ответы не отправляются новым внешним сервисам.

Интеграция: цикл в каждой главе; проект, повторение, интервью и пилот — отдельные маршруты с навигацией из курса. Лаборатории расширяют существующую страницу. Проверки: чистые модели, границы состояний, сохранение, ссылки, производственная сборка и браузерное прохождение.
