На этом этапе вы добавите поддержку распознавания числовых литералов.

### Ссылка на книгу

Код для этого этапа реализован в [разделе 4.6.2: Числовые литералы](https://craftinginterpreters.com/scanning.html#number-literals).

### Проверки

Тестирующая система выполнит серию проверок с файлами `test.lox`, содержащими числовые литералы вместе с ранее введёнными токенами.

Например, если `test.lox` содержит следующее:

```
42
```

Тестирующая система запустит вашу программу следующим образом:

```
$ ./your_program.sh tokenize test.lox
NUMBER 42 42.0
EOF  null
```

Как и строки, числовые литералы имеют связанное «значение литерала». Обратите внимание: значение целочисленного литерала представляется как "42.0" (с десятичной точкой). Это
соответствует [формату книги](https://github.com/munificent/craftinginterpreters/blob/01e6f5b8f3e5dfa65674c2f9cf4700d73ab41cf8/test/scanning/numbers.lox).

Вам также потребуется обрабатывать числа с десятичной точкой. Например, если `test.lox` содержит следующее:

```
1234.1234
```

Тестирующая система запустит вашу программу следующим образом:

```
$ ./your_program.sh tokenize test.lox
NUMBER 1234.1234 1234.1234
EOF  null
```

Тестирующая система выполнит несколько таких проверок со случайными токенами, например:

| Входные данные | Ожидаемый вывод |
| :---: | :-------------: |
| `1` | `NUMBER 1 1.0` |
| `2345.6789` | `NUMBER 2345.6789 2345.6789` |
| `42.0000` | `NUMBER 42.0000 42.0` |

Тестирующая система проверит, что stdout вашей программы соответствует приведённому выше формату.

### Примечания

- Этот формат вывода соответствует спецификации в [репозитории книги](https://github.com/munificent/craftinginterpreters/blob/01e6f5b8f3e5dfa65674c2f9cf4700d73ab41cf8/test/scanning/numbers.lox)
- Хотя поле `<LITERAL>` для целого числа представляется как "42.0" (с десятичной точкой), поле `<LEXEME>` будет содержать целочисленное значение без десятичной точки, поскольку
  оно представляет фактические символы, образовавшие токен.
- При выделении токенов допускаются непарные круглые или фигурные скобки. На следующих этапах, когда мы перейдём к синтаксическому анализу выражений, такие случаи будут отмечаться как ошибки.
