
# Семь проверяемых этапов и самостоятельная защита

Проходите главы /backend-path/book/01-start … /backend-path/book/08-defense по порядку. Каноническое чтение основ Go, конкурентности и проектирования систем указано в главах. Учебные материалы и оба архива доступны бесплатно.

В starter тесты целевого этапа сначала падают: это ожидаемые незавершённые TODO. Не требуйте PASS всех будущих этапов до реализации. Команды ниже проверяют текущий и прежние этапы. В reference все этапы реализованы; открывайте его после своей попытки и сравнивайте отдельный вопрос.

| Этап | Что реализовать | Команда из папки go.mod |
|---|---|---|
| 01 | Analyze: trim, uppercase, Fields; свой табличный тест | `go test ./... -run '^TestStage01' -count=1` |
| 02 | POST/GET, JSON, id, состояния, 400/404 | `go test ./... -run '^TestStage0[12]' -count=1` |
| 03 | Fixed workers, bounded queue, 429, 503, shutdown/cancel | `go test ./... -run '^TestStage0[123]' -count=1` |
| 04 | Снимок, ошибки сохранения/загрузки, восстановление | `go test ./... -run '^TestStage0[1-4]' -count=1` |
| 05 | Idempotency-Key, raw text, retry limit, отменяемая задержка | `go test ./... -run '^TestStage0[1-5]' -count=1` |
| 06 | Готовность и метрики состояний/повторов | `go test ./... -run '^TestStage0[1-6]' -count=1` |
| 07 | Конкурентный приём, результаты, дубли; отчёт по нагрузке/сбоям | `go test ./... -run '^TestStage0[1-7]' -count=1` |
| 08 | Защита архитектуры и самостоятельное требование двух клиентов | Собственные тесты и проверка README; TestStage08 в архиве нет |

Начиная с этапа 03 повторяйте целевую команду с `-race`, например:

```sh
go test -race ./... -run '^TestStage0[1-3]' -count=1
```

Перед переходом к следующему этапу объясните, что проверил тест и что осталось ручной проверкой. В первом этапе намеренно внесите ошибку, увидьте FAIL и восстановите реализацию. На следующих этапах добавляйте собственные тесты с префиксом TestStageNN, чтобы команды таблицы их запускали.

Тесты используют публичный API. Они проверяют наблюдаемые результаты, переполнение, остановку, восстановление, повторы и выбранные конкурентные сценарии. Они не доказывают понимание Go, безопасность API, сохранность при потере питания, производительность на другом железе или справедливость вашего решения восьмого этапа.

Для нагрузки запустите сервер отдельно, затем `go run ./cmd/load -requests 200 -concurrency 8 -url http://127.0.0.1:8080`. Этот клиент измеряет приём HTTP, не время завершения задания. Для отчёта отдельно наблюдайте принятые задания и метрики. Запишите условия и воспроизведите перегрузку управляемой Process, перезапуск и остановку с дедлайном.

Защита завершена, когда другой человек может по вашему README запустить проект, повторить эксперимент и понять границы. Самостоятельное изменение: горячий клиент A не должен бесконечно задерживать редкого B. Сначала задайте точное правило приёма и обслуживания, область ключей, условия обещания, восстановление и остановку; затем напишите свои тесты. Готовый алгоритм в эталон не включён.
