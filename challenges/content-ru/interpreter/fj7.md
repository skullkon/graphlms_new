На этом этапе вы добавите поддержку ошибок времени выполнения в свой интерпретатор Lox.

### Ссылка на книгу

Код для этого этапа реализован в [разделе 10.4: Объекты функций](https://craftinginterpreters.com/functions.html#function-objects).

### Проверки

Тестирующая система выполнит серию проверок с файлами `test.lox`, содержащими программы с ошибками времени выполнения.

Например, если `test.lox` содержит следующее

```
85();
```

Тестирующая система запустит вашу программу следующим образом:

```
$ ./your_program.sh run test.lox
Can only call functions and classes.
[line 1]
```

Тестирующая система выполнит несколько таких проверок со случайными выражениями, например:

Тестовый случай 1:

Входные данные:

```
"not a function"();
```

Ожидаемый вывод:

```
Can only call functions and classes.
[line 1]
```

Тестовый случай 2:

Входные данные:

```
fun f(a, b) {
  print a;
  print b;
}

f(1, 2, 3, 4);
```

Ожидаемый вывод:

```
Expected 2 arguments but got 4.
[line 6]
```

Тестовый случай 3:

Входные данные:

```
fun f(a, b) {}

f(1);
```

Ожидаемый вывод:

```
Expected 2 arguments but got 1.
[line 3]
```

Тестовый случай 4:

Входные данные:

```
false();
```

Ожидаемый вывод:

```
Can only call functions and classes.
[line 1]
```

Тестирующая система проверит, что stdout вашей программы соответствует приведённому выше формату, а код завершения равен 70.

### Примечания

- Этот формат вывода соответствует спецификации в [репозитории книги](https://github.com/munificent/craftinginterpreters/blob/4a840f70f69c6ddd17cfef4f6964f8e1bcd8c3d4/test/function/body_must_be_block.lox)
- Сообщения об ошибках следует выводить в `stderr`, а не в `stdout`.
- На этом этапе тестирующая система не проверяет точный текст ошибки, а только завершение программы с кодом 70.
