### Команда `parse`

На предыдущих этапах тестирующая система использовала команду `tokenize` для проверки вашей реализации лексического анализатора. В этом расширении ей потребуется проверить
реализацию синтаксического анализатора, поэтому она будет использовать другую команду: `parse`.

Команда `parse` принимает путь к файлу (например, `test.lox`) и выводит AST-представление его содержимого в stdout.

Например, если `test.lox` содержит следующее:

```
2 + 3
```

Команда `parse` вернёт следующее:

```
$ ./your_program.sh parse test.lox
(+ 2.0 3.0)
```

Этот формат вывода соответствует спецификации в [репозитории книги](https://github.com/munificent/craftinginterpreters/blob/01e6f5b8f3e5dfa65674c2f9cf4700d73ab41cf8/test/expressions/parse.lox).

Для того же файла вывод команды `tokenize` выглядел бы так:

```
$ ./your_program.sh tokenize test.lox
NUMBER 2 2.0
PLUS + null
NUMBER 3 3.0
EOF  null
```

### Проверки

Тестирующая система выполнит серию проверок с файлами `test.lox`, содержащими логические значения `true` и `false`, а также литерал `nil`.

Например, если `test.lox` содержит следующее:

```
true
```

Тестирующая система запустит вашу программу следующим образом:

```
$ ./your_program.sh parse test.lox
true
```

Тестирующая система проверит, что stdout вашей программы соответствует приведённому выше формату.

Список токенов, для которых нужно реализовать синтаксический анализ на этом этапе:

| Входные данные | Ожидаемый вывод |
| :---: | :-------------: |
| `true` | `true` |
| `false` | `false` |
| `nil` | `nil` |
