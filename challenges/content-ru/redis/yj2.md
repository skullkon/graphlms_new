На этом этапе вы добавите поддержку `GETBIT` для ключа, созданного командой `SET`.

### Строки и битовые карты

Поскольку битовые карты являются строками, побитовые команды работают с любыми строковыми значениями, включая ключи, созданные через `SET`.

Это два представления одних байтов: `SET` записывает строку, а `GETBIT` читает один её бит.

Например, ASCII-символ `A` — это байт `01000001`. Смещение `0` соответствует его старшему биту:

```bash
> SET mykey "A"
OK
> GETBIT mykey 1
(integer) 1
> GETBIT mykey 7
(integer) 1
> GETBIT mykey 0
(integer) 0
```

Здесь биты `1` и `7` установлены, а бит `0` — нет.

### Проверки

Тестирующая система запустит программу так:

```bash
$ ./your_program.sh
```

Затем сохранит однобайтовую строку командой `SET`. Например:

```bash
$ redis-cli SET mykey "A"
```

Далее отправит команды `GETBIT` для смещений в этой строке.

```bash
$ redis-cli GETBIT mykey 1
```

Ожидаемый ответ — `:1\r\n`, то есть 1 в формате [целого числа RESP](https://redis.io/docs/latest/develop/reference/protocol-spec/#integers).

```bash
$ redis-cli GETBIT mykey 7
```

Ожидаемый ответ — `:1\r\n`.

```bash
$ redis-cli GETBIT mykey 0
```

Ожидаемый ответ — `:0\r\n`.

### Примечания

- Здесь требуется только `GETBIT` для ключа, созданного через `SET`. Чтение битовой карты командой `GET` будет рассмотрено позже.
- Redis применяет `GETBIT` к байтам строки. Ключи, созданные через `SET` и `SETBIT`, имеют общее представление. См. [официальную реализацию](https://github.com/redis/redis/blob/e1d7d50f9c244ce52f724b279fcb19773fffa98c/src/bitops.c#L915-L917).
