На этом этапе вы будете передавать `COMP_LINE` и `COMP_POINT` как переменные окружения при вызове скрипта дополнения.

### Переменные окружения дополнения

На предыдущих этапах вы передавали имя команды, текущее и предыдущее слова как аргументы скрипта дополнения. Некоторым скриптам также нужны полная командная строка и положение курсора. Перед вызовом скрипта оболочка должна установить две переменные окружения:

- `COMP_LINE` — полный текст командной строки в момент нажатия TAB (без завершающего перевода строки).
- `COMP_POINT` — отсчитываемый от нуля байтовый индекс позиции курсора в `COMP_LINE`. При нажатии TAB в конце строки это длина `COMP_LINE`.

Например, если пользователь вводит:

```bash
$ git ad<TAB>
```

Оболочка должна установить:

- `COMP_LINE`: `git ad`
- `COMP_POINT`: `6` (длина строки `git ad` — 6 байт, а курсор находится в конце).

Они задаются как переменные окружения процесса дополнения, наряду с аргументами `argv[1]`, `argv[2]` и `argv[3]` из предыдущих этапов.

### Проверки

Тестирующая система запустит вашу программу следующим образом:

```bash
$ ./your_program.sh
```

Затем система зарегистрирует скрипт дополнения и вызовет дополнение:

```bash
$ complete -C /path/to/completer_script git
$ git ad<TAB>
$ git add 
```

Скрипт дополнения использует и аргументы argv, и переменные окружения, чтобы получить правильный вариант. Если `COMP_LINE` или `COMP_POINT` отсутствует или неверна, скрипт не вернёт правильный результат и дополнение не сработает.

Тестирующая система проверит, что:

- `COMP_LINE` содержит полный текст командной строки в момент нажатия TAB.
- `COMP_POINT` содержит правильный байтовый индекс позиции курсора.
- Результат дополнения корректен (что подтверждает правильную передачу обеих переменных окружения).

### Примечания

- `COMP_POINT` — индекс байта, а не символа. Для ASCII-ввода они совпадают, но различие важно при обработке многобайтовых символов.
- Эти переменные окружения следует задавать только для процесса дополнения, не сохраняя в окружении самой оболочки.
