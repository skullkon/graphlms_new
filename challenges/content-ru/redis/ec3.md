На этом этапе вы добавите `BLPOP`, которая блокируется до появления доступного для извлечения элемента.

### Команда `BLPOP`

[`BLPOP`](https://redis.io/docs/latest/commands/blpop/) — блокирующий вариант `LPOP`. Она ждёт появления элемента в списке и затем извлекает его.

Если список пуст, команда блокируется, пока:

- В список не добавят новый элемент.
- Или не истечёт указанное время ожидания.

Если время равно `0`, команда ждёт бессрочно.

Например, клиент может ждать элемент списка без ограничения времени так:

```bash
> BLPOP list_key 0
```

Клиент будет ждать добавления элемента в `list_key`. Когда появится элемент, например `"foobar"`, он удаляется из списка, а сервер отвечает [массивом RESP](https://redis.io/docs/latest/develop/reference/protocol-spec/#arrays):

```bash
1) "list_key"
2) "foobar"
```

Массив RESP содержит две объёмные строки:
1. Имя списка.
2. Извлечённый элемент.

Другие особенности `BLPOP`:

- Если задано время ожидания, оно измеряется в секундах.
- Если за это время не добавили ни одного элемента, сервер возвращает [нулевой массив](https://redis.io/docs/latest/develop/reference/protocol-spec/#null-arrays) (`*-1\r\n`).
- Если один список ждут несколько клиентов, сервер отвечает тому, кто ждёт дольше всех.

### Тесты

Тестирующая программа запустит вашу программу так:

```
./your_program.sh
```

Затем отправит `BLPOP` со временем ожидания `0`:

```bash
$ redis-cli BLPOP list_key 0
# (Blocks)
```

Через небольшой промежуток другой клиент добавит элемент в тот же список:

```bash
# In another client:
$ redis-cli RPUSH list_key "foo"
# Expect: (integer) 1
```

Тест ожидает, что первый клиент немедленно получит ответ — массив `["list_key", "foo"]` в RESP.

```bash
# RESP encoding of ["list_key", "foo"]
*2\r\n
$8\r\n
list_key\r\n
$3\r\n
foo\r\n
```

Тест также проверит `BLPOP` с несколькими ожидающими клиентами. Он создаст несколько клиентов, каждый из которых отправит `BLPOP` для одного списка.

```bash
# Client 1 sends BLPOP first
$ redis-cli BLPOP another_list_key 0

# Client 2 sends BLPOP second
$ redis-cli BLPOP another_list_key 0
```

Затем отдельный клиент добавит элемент через `RPUSH`.

```
$ redis-cli RPUSH another_list_key "foo"
```

Сервер должен ответить клиенту, отправившему `BLPOP` первым (`Client 1`).

### Примечания

- Пока время ожидания всегда будет `0`, то есть `BLPOP` должна ждать бессрочно. Ненулевые значения появятся позже.
