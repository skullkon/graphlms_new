На этом этапе вы добавите передачу команд записи от ведущего одной реплике.

### Распространение команд

После завершения рукопожатия и отправки файла RDB ведущий начинает передавать реплике команды записи.

Команды записи меняют набор данных ведущего, например `SET` и `DEL`. Команды вроде `PING`, `ECHO` и других не считаются командами записи и не передаются репликам.

### Процесс передачи

Команды передаются через соединение репликации — то же соединение, которое использовалось для рукопожатия.

Команды отправляются как массивы RESP. Например, получив от клиента `SET foo bar`, ведущий отправит `*3\r\n$3\r\nSET\r\n$3\r\nfoo\r\n$3\r\nbar\r\n` всем подключённым репликам через их соединения репликации.

Реплики обрабатывают эти команды так же, как команды клиентов, с одним отличием: они не отправляют ведущему ответы. Они молча выполняют команду и обновляют своё состояние.

Ведущий тоже не ждёт ответа от реплики при передаче команды. Он отправляет команды по мере поступления.

Из правила «без ответа» есть исключение — команда `REPLCONF GETACK`. Её мы рассмотрим позже.

### Тесты

Тестирующая программа запустит вашу программу так:

```
./your_program.sh --port <PORT>
```

Затем подключится к TCP-серверу как реплика и выполнит полную последовательность рукопожатия из предыдущих этапов.

После этого она дождётся отправки файла RDB сервером.

Получив RDB, тестирующая программа отправит вашей программе серию команд записи как отдельный клиент Redis.

```bash
$ redis-cli SET foo 1
$ redis-cli SET bar 2
$ redis-cli SET baz 3
```

Затем проверит, что команды переданы реплике в правильном порядке. Команды должны быть:

- Закодированы как массивы RESP.
- Отправлены по тому же соединению, что использовалось для рукопожатия (соединению репликации).

### Примечания

- Хотя реплики указывают `listening-port` при рукопожатии, он нужен только для [мониторинга и журналирования](https://github.com/redis/redis/blob/90178712f6eccf1e5b61daa677c5c103114bda3a/src/replication.c#L107-L130). Redis передаёт команды по TCP-соединению, открытому репликой при рукопожатии.
- Полноценная реализация буферизовала бы команды до завершения загрузки RDB репликой. В этом задании можно считать, что реплика готова принимать команды сразу после получения файла RDB.
