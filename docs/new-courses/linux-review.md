# Независимая проверка курса Linux

Проверка 30 сентября 2026 года. Прочитаны все 14 глав `site/content/linux/book`, README и три программы `tools/linux-labs`, включая фикстуры через smoke. Материалы Linux не изменялись. Проверял путь новичка, последовательность shell-понятий, границы Ubuntu/хоста/WSL, ожидаемые отказы и безопасность локальных опытов.

## Результат проверки

Последовательность пригодна для человека без опыта администрирования: отдельная Ubuntu → модель системы → аргументы и пути → файлы → потоки/статусы → права → процессы → пакеты → окружение → скрипт → сеть → служба → восстановление → финал. Предпосылки для скрипта и сетевого опыта объяснены до использования. Права меняются на собственных объектах, сигналы направляются своим процессам, сервер ограничен loopback и учебной папкой. Внешний аккаунт и платный экзамен не требуются.

Курс честно разделяет переносимую демонстрацию и Linux-часть. Проверка systemd PID1 не выдаётся за доступность пользовательского manager; отсутствие bus имеет ручную альтернативу. WSL не объявляется обычной VM без оговорок. [Документация Microsoft](https://learn.microsoft.com/en-us/windows/wsl/systemd) подтверждает поддержку systemd с зависимостью от версии/конфигурации; служба сама по себе также не обещает удерживать WSL запущенной.

Команда `bash tools/linux-labs/smoke.sh` выполнена успешно на Darwin/macOS обычным пользователем: пять групп PASS, включая отказ записи, независимую копию и ссылку, форматы отчёта, архив/восстановление, локальный HTTP/404/остановку. Синтаксис `bash -n tools/linux-labs/smoke.sh tools/linux-labs/report.sh` также прошёл. Файл report.sh дословно совпадает с heredoc десятой главы. Рабочие артефакты smoke сохранены в `/var/folders/5q/yxftvw111cgb3klhgflnrh8h0000gn/T/linux-labs.mo2WpM`.

Это не проверка Ubuntu, APT, /proc, ip, ss или systemd на Linux. На этой машине эти runtime-сценарии не исполнялись; README и финальное сообщение smoke корректно называют ограничение.

## Замечания для автора

### P2 — ручная ветка главы 12 зависит от подготовки внутри systemd-ветки

Место: `site/content/linux/book/12-services-logs.mdx`, строка 21 и раздел «Переносимый путь без manager». Инструкция после отказа `systemctl --user` предлагает перейти к ручному пути. Но создание `~/linux-course-service/site/index.html` находится ниже в разделе «Unit описывает работу» (строки 27–31). Если новичок последует условному маршруту и пропустит systemd-раздел, каталог ручного опыта не существует. Перенаправление в `~/linux-course-service/server.log` откажет ещё до запуска Python; при существующем каталоге без index сервер вернёт не ожидаемую страницу.

Исправление: вынести создание учебной папки и index в явно общую подготовку перед развилкой либо повторить необходимые шаги в ручном разделе. При недоступном manager ученик должен пройти самостоятельную цепочку подготовка → запуск → готовность → curl → журнал → stop, не создавая unit или папку systemd.

### P2 — неверный путь изменяемого исходника в главе 13

Место: `site/content/linux/book/13-storage-backup.mdx`, строка 51: «Теперь измените source/notes.txt». Пример создал `source/docs/notes.txt`, и cmp проверяет именно этот путь. Новичок может создать другой файл или получить отказ отсутствующего пути и не воспроизвести сравнение сохранённой и новой версии.

Исправление: назвать `"$backup_lab_dir/source/docs/notes.txt"` и прежний восстановленный `"$backup_lab_dir/restore/docs/notes.txt"`; после изменения показать ожидаемый ненулевой cmp и объяснить, что это намеренное различие, не ошибка архива. Затем при повторном извлечении проверять новую пустую папку.

### P3 — готовность после systemctl start отличается от запуска процесса

Место: `site/content/linux/book/12-services-logs.mdx`, строки 53–63. У Type=simple успешный start/active ещё не является ожиданием готового Python HTTP endpoint. В ручной ветке отдельно сказано, что первый curl может опередить запуск; аналогичное условие желательно явно распространить и на systemd-вариант.

Исправление: дать короткий ограниченный повтор curl до ожидаемого ответа либо предложить повтор после записи прослушивания в журнале. Не засчитывать единичный первоначальный connect failure сразу как неверную конфигурацию. Содержательное различие active и HTTP уже объяснено верно; нужен мост к воспроизводимому первому опыту.

## Проверка после правок

Повторить ручной маршрут главы 12 в новой среде без пользовательского manager и без заранее созданной папки linux-course-service. Для главы 13 повторить создание архива, изменение docs/notes и чтение сохранённой версии. На Ubuntu отдельно подтвердить systemd-путь с доступным manager, включая готовность и остановку. Изменения двух текстовых мест не требуют повторной установки Ubuntu или запуска системных команд от root.
