На этом этапе вы добавите поддержку синтаксических ошибок в свой интерпретатор. Синтаксические ошибки возникают, когда код не соответствует правильному синтаксису.

### Ссылка на книгу

Код для этого этапа реализован в [разделе 9.5: Циклы for](https://craftinginterpreters.com/control-flow.html#for-loops).

### Проверки

Тестирующая система выполнит серию проверок с файлами `test.lox`, содержащими программы с синтаксическими ошибками.

Например, если `test.lox` содержит следующее

```
for (;;) var foo;
```

Тестирующая система запустит вашу программу следующим образом:

```
$ ./your_program.sh run test.lox
[line 1] Error at 'var': Expect expression.
```

Тестирующая система выполнит несколько таких проверок со случайными выражениями, например:

Тестовый случай 1:

Входные данные:

```
if (true) "ok"; else var foo;
```

Ожидаемый вывод:

```
[line 1] Error at 'var': Expect expression.
```

Тестовый случай 2:

Входные данные:

```
for (var a = 1; {}; a = a + 1) {}
```

Ожидаемый вывод:

```
[line 2] Error at '{': Expect expression.
[line 2] Error at ')': Expect ';' after expression.
```

Тестовый случай 3:

Входные данные:

```
for (var a = 1; a < 2; {}) {}
```

Ожидаемый вывод:

```
[line 2] Error at '{': Expect expression.
```

Тестовый случай 4:

Входные данные:

```
for ({}; a < 2; a = a + 1) {}
```

Ожидаемый вывод:

```
[line 2] Error at '{': Expect expression.
[line 2] Error at ')': Expect ';' after expression.
```

Тестирующая система проверит только то, что при ошибке компиляции код завершения равен 65.

### Примечания

- Этот формат вывода соответствует спецификации в [репозитории книги](https://github.com/munificent/craftinginterpreters/blob/4a840f70f69c6ddd17cfef4f6964f8e1bcd8c3d4/test/if/dangling_else.lox)
- Сообщения об ошибках следует выводить в `stderr`, а не в `stdout`.
- На этом этапе тестирующая система не проверяет точный текст ошибки, а только завершение программы с кодом 65.
