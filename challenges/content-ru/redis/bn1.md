На этом этапе вы добавите команду `UNWATCH`.

### Команда `UNWATCH`

Команда [`UNWATCH`](https://redis.io/docs/latest/commands/unwatch/) очищает все отслеживаемые ключи текущего соединения. Ключи, ранее зарегистрированные через `WATCH`, больше не отслеживаются, и их изменения не влияют на будущие транзакции.

```bash
$ redis-cli
> WATCH foo bar
OK
> UNWATCH
OK
```

Ответ всегда равен `+OK\r\n`.

После `UNWATCH` следующая транзакция выполняется обычным образом, даже если другой клиент изменит ранее отслеживаемые ключи.

### Тесты

Тестирующая программа запустит вашу программу так:

```bash
$ ./your_program.sh
```

Тест создаст двух клиентов. Первый задаст два ключа и начнёт их отслеживать:

```bash
# Client 1
> SET foo 100
OK
> SET bar 200
OK
> WATCH foo bar
OK
```

Второй изменит один из этих ключей:

```bash
# Client 2
> SET foo 200
OK
```

Первый снимет наблюдение со всех ключей, затем начнёт и выполнит транзакцию:

```bash
# Client 1
> UNWATCH
OK
> MULTI
OK
> SET foo 400
QUEUED
> EXEC
1) OK                  # transaction succeeds, keys were unwatched

# Client 2
> GET foo
"400"                  # confirms the transaction's write took effect
```

Будет проверено, что:

- `UNWATCH` возвращает `+OK\r\n`.
- `EXEC` успешна, несмотря на изменение ранее отслеживаемого ключа, поскольку `UNWATCH` очистила состояние наблюдения.
- Команды транзакции применены.

### Примечания

- `UNWATCH` не принимает аргументы и всегда очищает все отслеживаемые ключи соединения.
- `UNWATCH` должна работать и без отслеживаемых ключей, просто возвращая `+OK\r\n`.
