## Идея решения

Буфером владеет одна горутина. Она сбрасывает непустую пачку по размеру
или по таймеру, затем заново отсчитывает интервал. `Stop` закрывает вход
и ждёт сброса остатка.

## Эталон

```go
package solution

import "time"

const (
	batchSize     = 100
	flushInterval = 50 * time.Millisecond
)

// Batcher накапливает события и сбрасывает их пачкой по размеру или по таймеру.
type Batcher struct {
	in    chan Event
	done  chan struct{}
	flush func(batch []Event)
}

// NewBatcher создаёт Batcher: flush при накоплении 100 событий ИЛИ через 50ms
// после последнего сброса.
func NewBatcher(flush func(batch []Event)) *Batcher {
	b := &Batcher{
		in:    make(chan Event),
		done:  make(chan struct{}),
		flush: flush,
	}
	go b.run()
	return b
}

func (b *Batcher) run() {
	defer close(b.done)

	buf := make([]Event, 0, batchSize)
	timer := time.NewTimer(flushInterval)
	defer timer.Stop()

	doFlush := func() {
		if len(buf) == 0 {
			return
		}
		batch := make([]Event, len(buf))
		copy(batch, buf)
		b.flush(batch)
		buf = buf[:0]
	}

	resetTimer := func() {
		if !timer.Stop() {
			select {
			case <-timer.C:
			default:
			}
		}
		timer.Reset(flushInterval)
	}
	for {
		select {
		case ev, ok := <-b.in:
			if !ok {
				doFlush()
				return
			}
			buf = append(buf, ev)
			if len(buf) >= batchSize {
				doFlush()
				resetTimer()
			}
		case <-timer.C:
			doFlush()
			resetTimer()
		}
	}
}

// Add добавляет событие в батчер.
func (b *Batcher) Add(event Event) {
	b.in <- event
}

// Stop сбрасывает остаток и корректно останавливает фоновую горутину.
func (b *Batcher) Stop() {
	close(b.in)
	<-b.done
}
```

## Почему это работает

`Timer` отличается от периодического `Ticker`: сброс по размеру начинает
новый отсчёт, поэтому ближайший старый тик не сбросит следующую пачку раньше.
Таймер перезапускается после возврата `flush`. Планировщик и длительность
самого `flush` могут задержать обработку; таймер не обещает точного времени.

`resetTimer` выполняет `Stop` и неблокирующее чтение только в горутине-владельце.
Это совместимо и со старой семантикой каналов таймера. Начиная с Go 1.23
при новом режиме таймеров `Reset` сам гарантирует отсутствие старого значения;
режим зависит от версии в `go.mod` и `GODEBUG=asynctimerchan`.

Копия пачки отделяет данные колбэка от массива, который переиспользует батчер.
Если колбэк хранит срез или читает его асинхронно, следующие события его не затрут.
Сам по себе синхронный вызов без копии не обязательно создаёт гонку.

Вход небуферизованный: `Add` ждёт готовности горутины-владельца и может ждать
всё время медленного `flush`. Это backpressure, а не неблокирующая операция.
Все `Add` должны завершиться до единственного `Stop`; отправка после закрытия
входа паникует. `flush` должен возвращаться, иначе `Stop` тоже не завершится.

Память буфера — O(batchSize), копирование одной пачки — O(её размера).
Буферизация входа может смягчить всплеск, но не устраняет backpressure при
постоянно более медленном потребителе. См. [select](/book/select) и [каналы](/book/channels).
