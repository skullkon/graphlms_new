На этом этапе вы расширите команду [INFO](https://redis.io/commands/info/), чтобы она отражала роль сервера как реплики.

### Флаг `--replicaof`

По умолчанию сервер Redis принимает роль ведущего. При передаче флага `--replicaof` он становится репликой.

Например:

```
./your_program.sh --port 6380 --replicaof "localhost 6379"
```

Здесь флаг `--replicaof` запускает сервер Redis как реплику. Сервер слушает соединения на порту `6380`, а также подключается к ведущему — другому серверу Redis на `localhost:6379` — и воспроизводит все его изменения.

Подробнее о работе репликации вы узнаете позже.

Пока нужно обновить обработчик `INFO replication`, чтобы он проверял конфигурацию сервера:

- Если пользователь не передал `--replicaof`, отвечать `role:master`.
- Если пользователь передал `--replicaof`, отвечать `role:slave`.

### Тесты

Тестирующая программа запустит вашу программу так:

```
./your_program.sh --port <PORT> --replicaof "<MASTER_HOST> <MASTER_PORT>"
```

Затем отправит серверу `INFO` с аргументом `replication`.

```bash
$ redis-cli -p <PORT> INFO replication
```

Программа должна ответить [объёмной строкой](https://redis.io/docs/latest/develop/reference/protocol-spec/#bulk-strings), каждая строка которой — пара «ключ — значение», разделённая двоеточием (`:`). Тест найдёт ключ `role` и проверит, что его значение — `slave`.

### Примечания

- Программа должна по-прежнему проходить предыдущие тесты: без `--replicaof` роль по умолчанию — `master`.
- Как и раньше, пока достаточно ключа `role`. Остальные появятся позже.
- На этом этапе ещё не нужно подключаться к ведущему, заданному через `--replicaof`. Это появится позже.
