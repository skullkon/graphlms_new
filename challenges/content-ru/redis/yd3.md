На этом этапе вы расширите `REPLCONF GETACK`, чтобы ответ содержал количество байтов команд, обработанных репликой.

### Напоминание о подтверждениях ACK

Ведущий использует ACK, чтобы проверять синхронизацию реплик и отсутствие отставания. Каждый ACK содержит смещение — количество байтов команд, обработанных репликой.

### Отслеживание смещения

Реплика обновляет смещение, учитывая полный размер в байтах каждой команды от ведущего. Учитываются как команды записи, например `SET`, `DEL`, так и остальные команды, например `PING`, `REPLCONF GETACK *`.

После обработки команды, например `["SET", "foo", "bar]`, реплика прибавляет полную длину её массива RESP в байтах к текущему смещению.

Важное правило: возвращаемое смещение включает только команды, обработанные **до** текущего запроса `REPLCONF GETACK *`.

Например:

- Реплика подключается, завершает рукопожатие, и ведущий отправляет `REPLCONF GETACK *`.
  - Реплика отвечает `REPLCONF ACK 0`: до этого запроса команды ещё не обрабатывались.
- Затем ведущий отправляет ещё один `REPLCONF GETACK *`.
  - Реплика отвечает `REPLCONF ACK 37`, поскольку предыдущая команда `REPLCONF` заняла 37 байт.
- Ведущий отправляет `PING`.
  - Реплика молча обрабатывает команду, увеличивает смещение на 14 и не отправляет ответ.
- Приходит следующий `REPLCONF GETACK *`.
  - Реплика отвечает `REPLCONF ACK 88`: 37 за первый `REPLCONF`, +37 за второй `REPLCONF`, +14 за `PING`.

Сам текущий запрос `GETACK` в возвращаемое смещение не включается.

### Тесты

Тестирующая программа запустит вашу программу так:

```
./your_program.sh --port <PORT> --replicaof "<HOST> <PORT>"
```

Как и раньше, реплика должна завершить рукопожатие с ведущим и получить пустой RDB.

Затем ведущий передаст реплике серию команд, чередуя их с `REPLCONF GETACK *`.

```bash
REPLCONF GETACK *    # expect: REPLCONF ACK 0

PING                 # replica processes silently
REPLCONF GETACK *    # expect: REPLCONF ACK 51
# 51 = 37 (first REPLCONF) + 14 (PING)

SET foo 1             # replica processes silently
SET bar 2             # replica processes silently
REPLCONF GETACK *    # expect: REPLCONF ACK 146
# 146 = 51 + 37 (second REPLCONF) + 29 (SET foo) + 29 (SET bar)
```

Реплика должна вычислять и возвращать точное смещение на каждом шаге в ответе `REPLCONF ACK <offset>`. Ответ также должен быть [массивом RESP](https://redis.io/docs/latest/develop/reference/protocol-spec/#arrays).

### Примечания

- Смещение должно включать только байты команд, обработанных **до** получения текущей команды `REPLCONF GETACK`.
- Хотя ведущие не пересылают клиентские `PING` репликам, поскольку это не команды записи, они могут сами отправлять `PING`, чтобы сообщить репликам, что ведущий ещё работает.
