На этом этапе вы расширите журналирование AOF для нескольких команд записи.

### Добавление нескольких команд

Каждая команда записи должна добавляться в конец файла AOF в порядке поступления, формируя полный журнал изменений. Это относится к любой команде, меняющей данные, например `SET`, `DEL`, `INCR`, `LPUSH` и другим, а не только к `SET`.

Например, если сервер получает:

```bash
$ redis-cli SET foo 100
$ redis-cli SET bar 200
```

Файл AOF должен содержать обе команды по порядку:

```
*3\r\n
$3\r\n
SET\r\n
$3\r\n
foo\r\n
$3\r\n
100\r\n
*3\r\n
$3\r\n
SET\r\n
$3\r\n
bar\r\n
$3\r\n
200\r\n
```

*(Для удобства чтения последовательности `\r\n` выше показаны на отдельных строках. В настоящем файле каждая команда — непрерывная последовательность байтов.)*

Каждая команда добавляется непосредственно после предыдущей, без разделителей. При воспроизведении структуры RESP (`*3\r\n...`) достаточно, чтобы определить границы команд.

### Тесты

Тестирующая программа создаст внутри `<dir>/<append_dir_name>`:

- Манифест, в котором запись `type i` указывает на файл `<random_file_name>.1.incr.aof`.
- Соответствующий пустой файл AOF: `<random_file_name>.1.incr.aof`.

Она запустит вашу программу так:

```bash
$ ./your_program.sh --dir <dir> --appendonly yes --appenddirname <append_dir_name> --appendfilename <append_file_name> --appendfsync always
```

Затем отправит две команды записи с разными ключами:

```bash
$ redis-cli SET <key1> <value1>
$ redis-cli SET <key2> <value2>
```

Будет проверено, что:

- Обе команды присутствуют в файле AOF в порядке отправки.
- Каждая команда закодирована в корректном формате RESP.
- Записи сброшены на диск до получения ответа клиентом, поскольку `appendfsync` равен `always`.

### Примечания

- Если ваша реализация уже добавляет данные в конец файла, а не перезаписывает его, этот этап может пройти без изменений.
- Для определения файла записи необходимо прочитать манифест. Тест использует нестандартное имя файла.
- На этом этапе не нужно поддерживать `--appendfsync everysec`.
