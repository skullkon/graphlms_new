На этом этапе вы реализуете ответ Fetch для топика с одним сообщением, прочитав его с диска.

🚧 **Мы ещё готовим инструкции для этого этапа**. Ниже приведено описание работы тестирующей системы.

### Тесты

Тестирующая система запустит вашу программу следующим образом:

```bash
$ ./your_program.sh
```

Затем подключится к серверу на порту 9092 и отправит запрос `Fetch` (v16). Он содержит один топик с существующим идентификатором. В топике находится одно сообщение.

Она проверит, что:

- Первые 4 байта ответа («длина сообщения») корректны.
- Идентификатор корреляции в заголовке ответа совпадает с идентификатором в заголовке запроса.
- Код ошибки в теле ответа равен `0` (нет ошибки).
- Поле `throttle_time_ms` ответа равно `0`.
- Поле `responses` ответа содержит 1 элемент, в котором:
  - Поле `topic_id` совпадает со значением из запроса.
  - Массив `partitions` содержит 1 элемент, в котором:
    - Поле `partition_index` равно `0`.
    - Поле `error_code` равно `0` (нет ошибки).
    - Массив `records` содержит 1 элемент.
      - Всё содержимое `RecordBatch` прочитано с диска. Для проверки мы сравним содержимое `RecordBatch` с содержимым файла журнала.

### Примечания

- На этом этапе нужно разобрать запрос `Fetch`, чтобы получить `topic_id` для ответа.
- Официальная документация запроса `Fetch` находится [здесь](https://kafka.apache.org/42/design/protocol/#The_Messages_Fetch). Прокрутите до раздела «Fetch Response (Version: 16)».
