На этом этапе вы реализуете команду `WAIT` на ведущем сервере.

### Команда `WAIT`

Команда `WAIT` проверяет, сколько реплик подтвердили все предыдущие команды записи. Так клиент может оценить надёжность сохранения записи, прежде чем считать её успешной.

Формат команды:

```bash
WAIT <numreplicas> <timeout>
```

Значения аргументов:

- `<numreplicas>`: минимальное число реплик, которые должны подтвердить все предыдущие команды записи.
- `<timeout>`: максимальное время ожидания клиента в миллисекундах.

Например:

```bash
$ redis-cli WAIT 3 5000
(integer) 2
```

Здесь клиент просит ведущего дождаться `3` реплик с максимальным ожиданием 5000 мс. После истечения времени у ведущего подключены только `2` реплики, поэтому он сразу отвечает `2` в виде [целого числа RESP](https://redis.io/docs/latest/develop/reference/protocol-spec/#integers).

Пока обработаем простейший случай: клиенту нужны `0` реплик, и у ведущего нет подключённых реплик. В этом случае `WAIT` должна немедленно вернуть `0`.

Подсчёт реплик и соответствующие ответы появятся позже.

### Тесты

Тестирующая программа запустит вашу программу так:

```
./your_program.sh
```

Затем подключится к ведущему и отправит:

```bash
$ redis-cli WAIT 0 60000
```

Ожидается немедленный ответ `0` в виде целого числа RESP, поскольку реплики не подключены.
