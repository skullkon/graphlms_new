На этом этапе вы расширите встроенную команду `jobs` для обработки завершившихся фоновых заданий.

### Обработка завершившихся фоновых заданий

Сейчас, когда фоновый процесс вашей оболочки завершается, он становится зомби-процессом: выполнение окончено, но запись остаётся в таблице процессов, пока родительский процесс не подтвердит завершение. Оболочка должна получить сведения о завершении этих процессов, чтобы очистить их записи.

Когда пользователь запускает `jobs`, оболочка должна:
1. Проверить, завершилось ли каждое фоновое задание.
2. Если задание завершилось, отобразить его со статусом `Done` в текущем выводе.
3. Удалить задание `Done` из таблицы заданий, чтобы оно не появлялось при следующих вызовах `jobs`.

Например:
```bash
$ sleep 1 &
[1] 84470
# After ~1 second, the process has exited
$ jobs
[1]+  Done                    sleep 1
# The next jobs call shows nothing (job was removed)
$ jobs
$
```

Обратите внимание: у записи `Done` нет завершающего `&`, в отличие от записей `Running`.

### Обнаружение завершения процесса

Механизм проверки завершения каждого фонового задания зависит от языка, но общий подход заключается в проверке состояния процесса без ожидания его завершения.

Например:
- В C/Unix: используйте `waitpid(pid, &status, WNOHANG)` и проверьте `WIFEXITED(status)`.
- В Python: используйте `subprocess.Popen.poll()` и проверьте, что код завершения не равен `None`.
- В Node.js: прослушивайте событие `exit` дочернего процесса.

На этом этапе обрабатывайте только нормальное завершение. О процессах, убитых сигналами или остановленных, пока не беспокойтесь. Достаточно определить нормальное завершение процесса.

### Проверки

Тестирующая система запустит вашу программу следующим образом:
```bash
$ ./your_program.sh
```

Затем система запустит фоновое задание и проверит его с помощью `jobs`:
```bash
$ cat /path/to/fifo &
[1] 84470
$ jobs
[1]+  Running                 cat /path/to/fifo &
$ 
```

Тестирующая система запишет данные в FIFO, чтобы процесс `cat` завершился:
```bash
$ echo -ne "" > /path/to/fifo
```

Следующий вызов `jobs` должен показать завершившееся задание:
```bash
$ jobs
[1]+  Done                    cat /path/to/fifo
```

Следующий после этого вызов `jobs` не должен ничего показать:
```bash
$ jobs
$ 
```

Тестирующая система проверит, что:
- Первый вызов `jobs` показывает задание как `Running` с завершающим `&`.
- Второй вызов `jobs` показывает задание как `Done` без завершающего `&`.
- Третий вызов `jobs` не показывает заданий (завершившееся задание удалено).

### Примечания

- На этом этапе достаточно обработать одно фоновое задание.
- Обнаруживайте только нормальное завершение процесса. Завершение сигналом и остановленные состояния обрабатывать не нужно.
