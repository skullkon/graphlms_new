На этом этапе вы запросите метаданные торрента у пира с помощью расширения метаданных.

### Сообщения расширения метаданных

Как упоминалось ранее, magnet-ссылка не содержит всех сведений из файла .torrent, например длины файла, длины фрагмента и хешей фрагментов.

Чтобы получить эти данные, клиент должен использовать сообщения [расширения метаданных](https://www.bittorrent.org/beps/bep_0009.html#extension-message).

Расширение метаданных поддерживает следующие типы сообщений:

- `request` (msg_type: 0).
  - Запрашивает фрагмент метаданных у пира.
- `data` (msg_type: 1).
  - Отправляет фрагмент метаданных пиру.
- `reject` (msg_type: 2).
  - Сообщает, что у пира нет запрошенного фрагмента метаданных.

`msg_type` — идентификатор типа сообщения внутри расширения метаданных.

Метаданные хранятся фрагментами по 16 КиБ. В рамках задания можно считать, что все метаданные торрента помещаются в один фрагмент.

На этом этапе вы реализуете отправку сообщения `request` (msg_type: 0). Другие значения `msg_type` мы рассмотрим позже.

### Сообщение метаданных `request`

Как было показано выше, сообщение `request` относится к расширению метаданных.

Обратите внимание: это сообщение `request` отличается от сообщения запроса (ID: 6) базового [протокола BitTorrent](https://www.bittorrent.org/beps/bep_0003.html).

Оно следует стандартному формату сообщений расширений BitTorrent:

- Префикс длины сообщения (4 байта).
- Идентификатор сообщения (1 байт).
    - Равен 20, поскольку сообщение реализовано расширением.
- Полезная нагрузка (переменный размер).
    - Идентификатор сообщения расширения (1 байт).
        - Это идентификатор расширения метаданных удалённого пира, полученный при рукопожатии расширений.
    - Словарь bencode (переменный размер).
        - Выглядит так: `{'msg_type': 0, 'piece': 0}` (закодирован как словарь bencode).
        - `msg_type` равен 0, поскольку это сообщение `request`.
        - `piece` — индекс запрашиваемого фрагмента метаданных, начиная с нуля.
            - В этом задании мы запрашиваем один фрагмент, поэтому значение всегда равно 0.

### Команда `magnet_info`

Для проверки программы на этом этапе вводится новая команда `magnet_info`. Она работает так:

```bash
$ ./your_program.sh magnet_info <magnet-link>
Tracker URL: http://bittorrent-test-tracker.codecrafters.io/announce
Length: 92063
Info Hash: d69f91e6b2ae4c542468d1073a71d4ea13879a7f
Piece Length: 32768
Piece Hashes:
6e2275e604a0766656736e81ff10b55204ad8d35
e876f67a2a8886e8f36b136726c30fa29703022d
f00d937a0213df1982bc8d097227ad9e909acc17
```

Чтобы получить эти сведения, программа должна:

- Разобрать magnet-ссылку и получить URL трекера.
- Выполнить GET-запрос трекеру и получить список пиров.
- Установить TCP-соединение с пиром и выполнить рукопожатие.
- Выполнить базовое рукопожатие.
- Отправить сообщение битового поля (можно пропустить в этом задании).
- Получить сообщение битового поля.
- Выполнить рукопожатие расширений.
- Отправить запрос метаданных (**этот этап**).
- Получить сообщение с метаданными (следующие этапы).
- Вывести полученные данные в приведённом выше формате.

### Тесты

Тестирующая система запустит вашу программу следующим образом:

```bash
$ ./your_program.sh magnet_info <magnet-link>
```

На этом этапе ожидаемого вывода нет: тестирующая система проверит только получение корректного запроса метаданных. Вывод мы проверим на следующих этапах.

### Примечания

- Если метаданные больше 16 КБ, нужно запрашивать несколько фрагментов, но в рамках задания фрагмент будет только один.
