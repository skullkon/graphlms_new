На этом этапе вы добавите поддержку задания срока действия ключа.

### Параметры команды `SET`

Команда `SET` принимает [необязательные аргументы](https://redis.io/docs/latest/commands/set/#options), меняющие её поведение.

Вот несколько параметров, которые можно использовать с `SET`:

```bash
# Set a key with a 10-second expiry
$ redis-cli SET mykey value EX 10
OK

# Set a key with a 1000-millisecond expiry
$ redis-cli SET mykey value PX 1000
OK
```

### Параметр `PX`

Параметр `PX` задаёт срок действия ключа в миллисекундах. По истечении этого срока ключ становится недоступен.

Например, клиент может задать ключ со сроком действия так:

```bash
$ redis-cli SET foo bar PX 100
OK
```

Эта команда присваивает ключу `foo` значение `bar` на 100 миллисекунд.

После истечения срока действия команда `GET` для этого ключа должна вернуть [нулевую объёмную строку](https://redis.io/docs/latest/develop/reference/protocol-spec/#null-bulk-strings) (`$-1\r\n`).

```bash
$ redis-cli GET foo
(nil)
```

### Тесты

Тестирующая программа запустит вашу программу так:

```bash
$ ./your_program.sh
```

Затем отправит серверу команду `SET`, задающую ключ со сроком действия:

```bash
$ redis-cli SET foo bar PX 100
```

Сразу после этого она отправит команду `GET` для получения значения ключа:

```bash
$ redis-cli GET foo
```

Ожидается ответ `$3\r\nbar\r\n`: строка `bar`, закодированная как объёмная строка.

Дождавшись истечения срока действия ключа, тестирующая программа отправит ещё одну команду `GET`:

```bash
$ sleep 0.2 && redis-cli GET foo
```

Ожидаемый ответ — нулевая объёмная строка (`$-1\r\n`).

### Примечания

- Как и имена команд, их аргументы нечувствительны к регистру. Поэтому `PX`, `px` и `pX` допустимы.
- Ключи, значения и сроки действия в тестах будут случайными, поэтому фиксированный ответ не позволит пройти этап.
