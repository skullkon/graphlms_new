# Лаборатории «Базы данных»

Нужен бесплатный локальный PostgreSQL 18 и `psql` той же ветки. Последний patch проверяйте на [официальной странице](https://www.postgresql.org/support/versioning/). Установщик для своей ОС выбирайте на [postgresql.org/download](https://www.postgresql.org/download/). Docker необязателен. Go требуется только в итоговом проекте; задания SQL выполняются без Go и без облачного аккаунта.

Создайте НОВУЮ локальную учебную базу. Например, при работающем сервере и настроенной локальной роли:

```sh
createdb db_course_library_2026
export DB_LAB_URL='postgresql://localhost/db_course_library_2026'
psql "$DB_LAB_URL" -f setup.sql
psql "$DB_LAB_URL" -f tests.sql
```

Не используйте существующую базу с пользовательскими данными. `createdb` при совпадении имени должен отказать; после такого отказа выберите другое новое имя и обновите URL. Credentials/host/port задаются по вашей локальной установке. Не публикуйте пароль в репозитории; URI выше предполагает уже настроенную локальную аутентификацию. `setup.sql` включает ON_ERROR_STOP и транзакцию, создаёт НОВУЮ схему `club` без IF NOT EXISTS; collision останавливает запуск и откатывает незавершённый setup. DROP и автоматической очистки чужих объектов нет.

Golden seed: 3 members, 3 books, 4 physical copies, 3 loans. Активны две выдачи Анны книги «Практика Go»; выдача Бориса книги «Запросы SQL» возвращена; у Веры истории нет. Одна физическая копия имеет не более одной активной выдачи; partial unique index защищает это правило.

Каждый автоматический опыт выполняйте в отдельном запуске psql:

```sh
psql "$DB_LAB_URL" -f indexes.sql
psql "$DB_LAB_URL" -f migration.sql
psql "$DB_LAB_URL" -f tests.sql
```

`tests.sql` проверяет seed/NULL/JOIN/active/anti-join и negative constraints. Изменения откатываются. `indexes.sql` создаёт только временную таблицу внутри транзакции, генерирует 100 тысяч строк, снимает планы до/после индекса и откатывает всё. Обязательны одинаковый результат и объяснение плана; фиксированный speedup не обещан. `migration.sql` — dry run добавления display_name; тоже rollback.

`transactions.sql` содержит комментированные сценарии с SESSION A/B и ручными BARRIER. Откройте два окна psql к своей новой базе и копируйте команды по меткам. Запуск файла сам по себе не проверяет конкуренцию. RESET допустим только после завершения обеих транзакций; он касается только учебных объектов. После опыта с постоянным COMMIT, меняющего golden dataset, создайте новую базу для seed tests.

## Restore drill

Из каталога лабораторий, с установленными pg_dump/pg_restore ветки 18:

```sh
pg_dump --format=custom --no-owner --file=library.dump "$DB_LAB_URL"
createdb db_course_library_restore_2026
export DB_RESTORE_URL='postgresql://localhost/db_course_library_restore_2026'
pg_restore --exit-on-error --single-transaction --no-owner --no-privileges \
  --dbname="$DB_RESTORE_URL" library.dump
psql "$DB_RESTORE_URL" -f tests.sql
```

Целевая база должна быть только что созданной и пустой; при collision createdb выберите новое имя, не продолжайте на прежней базе. Не используйте `--clean`: чужие объекты не удаляются. Не запускайте setup перед restore, иначе схема уже существует. Dump может содержать исполняемые определения: используем только собственный учебный архив, не случайный чужой файл. Успех команды ещё требует проверки строк и инвариантов. [Официальный SQL dump](https://www.postgresql.org/docs/18/backup-dump.html).

## Необязательный открытый разбор Go

В `go-client` находится полноценная читающая команда из главы 10. Нужны Go 1.23+ и доступ к бесплатным Go modules при первом скачивании драйвера. Зафиксирован pgx v5.7.2; это выбранная версия примера, не заявление о самом новом выпуске. Команда ничего не записывает в базе.

```sh
cd go-client
go mod download
go run . -member 1
go run . -member 2
go run . -member 3
```

DB_LAB_URL берётся из переменной окружения предыдущих шагов. Анна: active_loan=1000 и 1002; Борис: email=NULL, active_loan=none; Вера: active_loan=none. Неизвестный читатель: reader not found. Параметр SQL передаётся отдельно, Rows закрывается, Scan/Rows.Err проверяются, NULL email и loan обрабатываются, контекст ограничен тремя секундами. Лимит двух соединений служит маленькому читающему CLI, не является рекомендацией для рабочего сервера. Ошибка подключения не выводит DSN и пароль.

## Статус проверки

2026-09-30: исполнено на PostgreSQL 18.6 в отдельном временном кластере, доступном только через Unix socket. setup.sql, tests.sql, indexes.sql и migration.sql прошли; повторный setup остановился на существующей схеме, golden seed сохранился. Custom dump восстановлен в новую пустую базу, tests.sql прошёл после restore. Наблюдались Seq Scan до индекса и Index Only Scan после него; это результат конкретного опыта, не универсальное обещание плана или ускорения.

В двух отдельных соединениях реально проверены: потерянное обновление (финальное 1), Repeatable Read write skew (активных 1), ожидание общей guard-строки и новый count=2, Serializable SQLSTATE 40001, конкурентный unique index при ROLLBACK первого автора (второй проходит) и COMMIT (второй получает 23505). Golden seed повторно проверен после опытов. Файл transactions.sql сам по себе эти сценарии не исполняет.

Go-клиент собран и запущен с Go 1.25.6/pgx v5.7.2: проверены читатели 1, 2 и 3, включая NULL Бориса. На заведомо недоступном локальном порту команда завершилась с ошибкой без DSN. `go test ./...` подтвердил компиляцию; отдельных Go unit tests в этом примере нет.

Лаборатории не подключаются к рабочим БД и не создают платные ресурсы автоматически. Версия инструмента и ваш локальный план могут отличаться: проверяйте факты повторным запуском.
