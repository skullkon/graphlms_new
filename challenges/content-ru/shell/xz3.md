На этом этапе вы будете дополнять ввод до наибольшего общего префикса (LCP), если он есть у нескольких вариантов.

### Дополнение по наибольшему общему префиксу

Когда скрипт дополнения возвращает несколько вариантов, нужно обработать два случая:

- Если их общий префикс длиннее текущего ввода, дополните ввод до LCP.
- Иначе вызовите звуковой сигнал при первом нажатии Tab, а при следующих нажатиях выведите совпадения (как на предыдущих этапах).

Например, если скрипт возвращает `checkout` и `cherry-pick`, а пользователь ввёл `c`:

```bash
$ git c<TAB>
$ git che
```

Оба варианта начинаются с `che`, поэтому оболочка дополняет ввод до `che` и ждёт дальнейшего ввода. Без звукового сигнала и без списка вариантов.

### Проверки

Тестирующая система запустит вашу программу следующим образом:

```bash
$ ./your_program.sh
```

Система зарегистрирует скрипт дополнения, возвращающий `checkout` и `cherry-pick`:

```bash
$ complete -C /path/to/completer_script git
$ git c<TAB>
$ git che                  # LCP of checkout and cherry-pick
$ git chec<TAB>
$ git checkout             # only one match now, completes fully with trailing space
```

Тестирующая система проверит, что:

- Первое нажатие TAB дополняет ввод до наибольшего общего префикса, если он существует.
- Когда остаётся только один вариант, TAB дополняет слово полностью с пробелом в конце.
- Если LCP расширяет текущий ввод, звуковой сигнал не подаётся.

### Примечания

- LCP вычисляется по вариантам, возвращённым скриптом дополнения, а не по жёстко заданному списку.
- Если LCP равен уже введённому тексту (новых символов для добавления нет), обрабатывайте это как отсутствие общего префикса: подайте звуковой сигнал, а при следующем TAB покажите варианты.
