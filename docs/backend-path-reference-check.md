# Проверка эталона backend-пути

Эталон — учебный сервис на стандартной библиотеке Go, модуль example.com/backend-path, Go 1.25. Публичный API: jobs.New(Config), http.Handler, Analyze и Shutdown(ctx). Реализация проверена независимыми тестами общего набора и дополнительными проверками границ.

## Согласованные границы

- Нулевые Workers/QueueSize/MaxAttempts/RetryDelay задают значения 2/16/3/10ms; отрицательные значения отклоняются. Ограничения text (4096) и Idempotency-Key (128) измеряются в байтах; тело HTTP ограничено 64 KiB.
- Result — значение без изменяемых ссылочных полей. HTTP отдаёт копию состояния, снятую под mutex.
- Живая очередь ограничена QueueSize, число Process ограничено Workers. Восстановленные задания уже приняты до сбоя и могут временно превышать ёмкость. Новый приём запрещён с 429, пока сумма ожидающих восстановленных и живой очереди не ниже ёмкости.
- New возвращается, не дожидаясь Process. healthz остаётся доступной во время восстановления; размер остатка виден в metrics. Отдельного статуса «восстановление закончено» нет.
- Идемпотентность сравнивает исходный body.text до TrimSpace. Этот текст сохраняется в snapshot; job.text в HTTP нормализован.
- MaxAttempts действует на один цикл обработки. Attempts сохраняет суммарное число вызовов Process через перезапуски. Повторное выполнение после сбоя может добавить вызов сверх MaxAttempts в суммарном счётчике.
- Метрика retries считает дополнительные вызовы в одном цикле, а не сам факт восстановления после сбоя.
- Восстановление queued/running даёт повторное выполнение. Для Analyze оно безопасно; для внешнего эффекта нужны отдельные гарантии идемпотентности. Exactly-once не обещается.
- Shutdown прекращает приём и дренирует принятые задания. Дедлайн отменяет рабочий контекст; Process должна сама реагировать на отмену. Возврат Shutdown с ошибкой контекста не означает завершения функции, которая игнорирует отмену.
- Один App владеет одним DataFile. Temp-файл и Rename заменяют снимок целиком; многопроцессной блокировки, WAL и гарантии при потере питания нет.
- Ошибка сохранения переводит healthz в 503 и запрещает новый приём. При ошибке первого сохранения POST возвращает 503, задание удаляется из памяти. Ошибка последующего сохранения оставляет последнее состояние в памяти, а файл может содержать более старое состояние: после восстановления возможно повторное выполнение.

## Первичные источники

MaxBytesReader ограничивает тело; Decoder.DisallowUnknownFields отклоняет неизвестные поля, а отдельное чтение до EOF проверяет отсутствие второго JSON-значения. [net/http](https://pkg.go.dev/net/http#MaxBytesReader), [encoding/json](https://pkg.go.dev/encoding/json#Decoder.DisallowUnknownFields).

Cancel сообщает об отмене через контекст, но не ждёт остановки работы. [context](https://pkg.go.dev/context#CancelFunc). Закрытие канала и отправки должны быть согласованы: отправка в закрытый канал паникует. [Спецификация Go](https://go.dev/ref/spec#Close).

Rename имеет ограничения платформы: документация не обещает атомарность даже в одной папке на не-Unix системах. Снимок не следует называть универсальной транзакцией файловой системы. [os.Rename](https://pkg.go.dev/os#Rename). Сведения дополнительно сверены через go doc на Go 1.25.6.

## Границы проверки

Это законченный учебный сервис с локальным снимком для одного процесса. Проверки не доказывают сохранность при аварии питания, работу нескольких владельцев одного файла, отсутствие задержек файловой системы, принудительную остановку произвольной Process, универсальный лимит памяти или exactly-once для внешних эффектов. Завершённые задания сохраняются без удаления, поэтому память и размер снимка растут с историей. Process вызывается синхронно работником; лимит Workers относится к этим вызовам, а не к горутинам, которые пользовательская функция может создать сама. Паника пользовательской Process не перехватывается.

В этой модели сохранение полного снимка под mutex намеренно делает согласование очевидным. Оно замедляет запросы при росте истории; журнал, compaction, межпроцессная блокировка и внешняя БД относятся к дальнейшему развитию.
