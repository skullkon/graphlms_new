# Эталон: сервис фоновых заданий

Это законченная реализация ядра этапов 01–07. Все поставляемые TestStage должны проходить. Сначала сделайте собственную попытку в starter; этот архив распакуйте отдельно, чтобы сравнение не затёрло ваши исходники. Новое требование восьмого этапа нужно реализовать самостоятельно.

## Подготовка

Нужны Go 1.25 или новее, редактор и терминал. Проект использует только стандартную библиотеку: npm, Docker, база данных, аккаунт и платный API не нужны. Проверьте `go version`. Интернет нужен для скачивания архива и установки Go; у проекта нет внешних Go-зависимостей.

Распакуйте ZIP в отдельную папку. Внутри есть каталог `backend-path-reference`; в терминале перейдите именно в него, где лежит `go.mod`:

```sh
cd "путь к папке/backend-path-reference"
go version
go build ./...
```

Замените путь своим. Кавычки нужны для пробелов в имени папки. Команды работают также в PowerShell. Повторный `go mod init` не нужен: модуль уже объявлен. В учебнике путь начинается с «Основ Go», если вы ещё не можете самостоятельно написать функцию со структурой результата и запустить тест.

## Где находится код

- `internal/jobs/jobs.go` — функция Analyze, настройки, HTTP-обработчик и жизненный цикл приложения.
- `internal/jobs/stages_test.go` — общие публичные проверки семи этапов. Не меняйте ожидаемые ответы ради PASS.
- `cmd/server/main.go` — запуск сервера и обработка сигнала остановки.
- `cmd/load/main.go` — ограниченный локальный нагрузочный клиент.
- `STAGES.md` — последовательность этапов и команды проверки.

Свой тест добавляйте в `internal/jobs/own_test.go` с `package jobs`, импортом `testing` и именем `TestStage01OwnAnalyze` для первого этапа. Во втором используйте префикс `TestStage02`, и так далее: команды этапов тогда запускают и ваши проверки. Объявления функций и типов размещайте вне main; действия — внутри функций.

## Запуск и конфигурация

Из папки с `go.mod`:

```sh
go run ./cmd/server
```

По умолчанию сервер слушает `http://127.0.0.1:8080`, использует 2 обработчика и очередь вместимостью 16. Снимок находится в `jobs.json` относительно рабочей папки. Остановите сервер через Ctrl+C. Перед запуском второго сервера остановите первый или выберите другой адрес и другой файл.

Настройки окружения:

| Имя | Значение по умолчанию | Значение |
|---|---|---|
| ADDR | 127.0.0.1:8080 | Адрес HTTP-сервера |
| DATA_FILE | jobs.json | Путь к снимку; родительская папка должна существовать |
| WORKERS | 2 | Положительное число обработчиков |
| QUEUE_SIZE | 16 | Положительная вместимость живой очереди |

Например, в bash/zsh установите `export WORKERS=1`, а в PowerShell — `$env:WORKERS="1"`, затем запустите сервер. Смена папки запуска меняет относительный путь к файлу. Два процесса с общим DATA_FILE не поддерживаются.

В Go `jobs.Config` дополнительно задаёт `MaxAttempts`, `RetryDelay` и `Process(context.Context,string)(Result,error)`. Нулевые значения означают 2 workers, 16 queue, 3 попытки одного цикла и задержку 10ms. Отрицательные значения — ошибка. `Process` по умолчанию вызывает Analyze; подмена в тесте позволяет удержать работу или вернуть ошибку. Пустой `Config.DataFile` отключает запись на диск; серверная точка входа задаёт jobs.json явно.

## Договор HTTP

`POST /jobs` получает один JSON-объект `{"text":"hello go"}`. Неизвестные поля, лишний JSON после объекта, неверный тип, пустой или пробельный text отклоняются с 400. Тело ограничено 64KiB; обрезанный text — 4096 байт, Idempotency-Key — 128 байт. Это байты UTF-8, не число букв.

Успешный ответ — 202 и JSON с полями `id`, `text`, `status`, `result`, `attempts`, `error`. Идентификатор — строка. `text` хранится без краевых пробелов. `result` содержит `text` и `words`; до успешного расчёта его значения могут быть пустыми. 202 означает принятие, а не завершение. Статусы: queued → running → done либо failed. Незавершённая работа может вернуться в queued при восстановлении.

`GET /jobs/{id}` возвращает 200 и запись либо 404 для неизвестного id. На неподдерживаемом пути или методе эталон отвечает 404. Ошибочные ответы не обязаны быть JSON: клиент сначала проверяет статус.

Полный приём — 429; остановка или зафиксированная ошибка хранилища — 503. Невалидный вход проверяется до приёма. Необязательный `Idempotency-Key` связывается с исходным text **до trim**. Совпавшие ключ и исходный вход возвращают 202 с прежним id, включая повтор после перезапуска. Тот же ключ с другим входом — 409. Без ключа каждый запрос создаёт отдельное задание. Во время остановки повтор с ключом тоже не обходит закрытие приёма.

Пока сервер работает, во втором терминале:

```sh
curl -i -X POST http://127.0.0.1:8080/jobs -H 'Content-Type: application/json' -d '{"text":"hello go"}'
curl -i http://127.0.0.1:8080/jobs/ID
curl -i http://127.0.0.1:8080/healthz
curl http://127.0.0.1:8080/metrics
```

Замените ID номером из первого ответа. В PowerShell используйте `curl.exe`; если кавычки JSON не передаются верно, сохраните `{"text":"hello go"}` в request.json и передайте `--data-binary @request.json` вместо `-d`. Через httptest проверки API работают и без установленного curl.

`GET /healthz` возвращает 200 при готовности и 503 после начала остановки или ошибки хранилища. `GET /metrics` возвращает JSON queued/running/done/failed/retries/workers/capacity. Первые четыре — текущие числа записей по состояниям; workers и capacity — настроенные пределы. retries считает дополнительные попытки внутри циклов и сохраняется в снимке между перезапусками. Он не равен сумме attempts всех заданий. queued включает восстановленное ожидание: сразу после запуска оно может превышать capacity.

## Повторы, файл и остановка

Analyze удаляет краевые пробелы, переводит текст в верхний регистр и считает слова через strings.Fields. Внутренние пробелы в результате сохраняются. Внешних побочных эффектов у этой операции нет.

Временная ошибка узнаётся через `errors.Is(err, jobs.ErrRetryable)`. Она допускает повтор после RetryDelay, максимум MaxAttempts запусков **в одном цикле обработки**, включая первый. Другая ошибка приводит к failed. Поле attempts накопительное между перезапусками. Восстановление само по себе не увеличивает его; зарегистрированная новая попытка увеличивает. После сбоя новый цикл может довести суммарное attempts выше трёх.

Снимок хранит записи, исходный вход ключей и счётчик retries. done/failed восстанавливаются с результатом или ошибкой, queued/running снова ожидают обработки. Конечный backlog прежних running и queued может превышать размер живой очереди: обработчики его разбирают, а новые запросы при заполнении отклоняются. Отсутствие файла разрешено при первом запуске, повреждённый существующий файл вызывает ошибку New.

Замена временного файла через rename публикует целый снимок в рамках одного процесса. Здесь нет fsync и гарантии сохранности при любой потере питания. Нет транзакции между процессами. Расчёт мог завершиться до сохранения done и поэтому выполниться ещё раз после сбоя: это **at-least-once**, обработка как минимум один раз. Не переносите эту гарантию на письма, оплату или другие внешние эффекты без отдельной защиты от дублей.

`Shutdown(ctx)` прекращает приём и ждёт принятые задания. При дедлайне он отменяет worker context и возвращает ошибку ожидания. Process должна реагировать на ctx.Done: context не убивает произвольный бесконечный цикл. Возвращение по дедлайну не доказывает, что некооперативный код уже завершился. Серверная точка входа даёт остановке пять секунд.

## Локальная нагрузка

С работающим сервером выполните во втором терминале:

```sh
go run ./cmd/load -requests 200 -concurrency 8 -url http://127.0.0.1:8080
```

Клиент допускает 1–10000 запросов и 1–256 одновременных обращений; адрес должен быть localhost или loopback IP. Перенаправления он не следует, прокси окружения не использует. Каждый запуск получает новый префикс ключей, чтобы случайно не измерить повторы старых заданий.

Вывод разделяет HTTP 202/429/503, прочие ответы и сетевые ошибки. Сетевая ошибка чтения может сопровождать уже полученный HTTP-статус: эти группы не всегда взаимно исключаются. p50/p95/max — задержки HTTP-попыток, включая неуспешные. admission_rps — число 202 за время опыта; завершение фоновых заданий клиент не измеряет. Посмотрите /metrics после завершения очереди и сохраните параметры опыта.

429 допустим при перегрузке и сам по себе не делает клиент неуспешным. Код выхода 1 означает сетевую ошибку, 503 или неожиданный HTTP-ответ; 2 — неверные параметры. Быстрый Analyze может не заполнить очередь на этом запуске. Для воспроизводимой проверки переполнения используйте тест с управляемой медленной Process. Результат на одном компьютере не является обещанием production-производительности.

## Проверки и завершение

После решения всех семи этапов:

```sh
go test ./... -count=1
go test -race ./... -count=1
go build ./...
```

Для -race нужна поддерживаемая среда Go; в некоторых системах потребуется C-компилятор. Ошибка среды не равна проверке, завершившейся успешно. Отсутствие отчёта о гонке касается выполненных сценариев, а не любого будущего входа.

Восьмой этап — собственное изменение требований о справедливом обслуживании двух клиентов. Готового решения и автоматической оценки защиты в архиве нет. Завершённый учебный результат включает ваш README, схему, воспроизводимые опыты и свои тесты нового договора; чужой PASS не заменяет эту работу.
