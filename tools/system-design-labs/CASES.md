# Исполняемые модели поиска и журнала

Нужен Python 3.9 или новее со стандартной библиотекой. Сеть, аккаунт и ключи API не нужны. Откройте терминал в папке с `cases.py` и `test_cases.py`:

```sh
python3 -m unittest -v test_cases
```

В Windows при установленном Python можно использовать `py -3 -m unittest -v test_cases`. Девять проверок должны завершиться OK. SQLite создаётся только во временных папках тестов; пользовательские базы не затрагиваются.

`SearchIndex` моделирует обратный индекс, monotonic version и tombstone. Проверки показывают, что позднее событие не воскрешает удалённый объект и что актуальное разрешение фильтрует устаревший индекс. AND-поиск по словам не поддерживает морфологию, ранжирование, пагинацию или промышленную производительность. Проверка конфликта одной версии помогает обнаружить нарушение producer-протокола.

`Ledger` моделирует переводы в одной валюте между счетами одной SQLite-базы. BEGIN IMMEDIATE сериализует писателей; [SQLite описывает ограничения транзакций](https://www.sqlite.org/lang_transaction.html). Начальные балансы — bootstrap-данные, не проводки пополнения. При каждом переводе журнал и балансы изменяются в одной транзакции. У модели нет внешнего провайдера, шардов и распределённого консенсуса.

Тесты намеренно сталкивают две попытки потратить один баланс, отправляют параллельные повторы одного ключа, заново открывают базу и вводят отказ до commit. Проверяются сохранение общей суммы, неотрицательность и соответствие двух проводок принятой операции. Ни одна проверка не доказывает устойчивость к любой потере питания или готовность модели к работе с реальными деньгами.

У модели принят явный договор отказов: недостаток средств сохраняется в requests вместе с ключом и параметрами. Повтор не переоценивает такой запрос; для нового намерения нужен новый ключ. Невалидный вход и выход за диапазон отвергаются до создания принятого запроса. Суммы и балансы ограничены 2^63−1, тип баланса проверяется в SQLite: переполнение не может молча перевести значение в REAL.

Для самостоятельной работы сначала уберите сравнение версий SearchIndex: убедитесь, что проверка на переупорядочивание падает, затем восстановите код. Второе упражнение: добавьте частичный возврат с защитой суммарного лимита и собственную конкурентную проверку. Готового решения возврата здесь нет.
