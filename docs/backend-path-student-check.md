# Проверка бесплатного пути Go Backend

Это независимая проверка обещаний проекта и симуляция чтения начинающим студентом. Она не заменяет тестирование курса с людьми. Код приложения реализует другой агент; проверки используют только экспортированные функции, HTTP и файл состояния, созданный самим приложением.

## План до реализации

1. Чистая функция: пробелы, Unicode, пустой текст, количество слов; эталонные ответы вычислены вручную.
2. HTTP: принятие задачи, получение результата, неизвестный ID, неверный JSON и пустой ввод.
3. Ограничение ресурсов: фактически запущенные обработчики, заполненная очередь, отказ 429; ожидание работающих задач при завершении, таймаут и реакция обработчика на отмену.
4. Сохранение: готовый/неуспешный результат после повторного открытия; повтор queued/running из снимка, созданного работающим приложением; повреждённый JSON отклоняется.
5. Повторы запросов: один ID при одинаковом ключе и тексте, 409 при изменённом тексте; успешный третий вызов после двух временных ошибок; предел попыток и постоянная ошибка без повторов.
6. Наблюдаемость: здоровье до/после остановки и согласованные счётчики состояния/повторов.
7. Параллельные HTTP-запросы: принимаемые задачи имеют отдельные ID и правильные результаты, повтор одного ключа не создаёт дубликаты. Проверка результата, а не нестабильный порог скорости.

Нагрузочный клиент будет выполнять ограниченную серию POST на локальный сервис с уникальным префиксом ключей на запуск. Отчёт содержит p50/p95/max задержки HTTP-ответа, принятые 202, ожидаемые отказы 429, отказы 503, прочие HTTP-ответы и сетевые ошибки. `admission RPS` означает число принятых запросов в секунду измерения; завершение фоновой обработки измеряется отдельно и не выводится из этого числа.

## Результаты выполнения и чтения

Проверки находятся в `tools/backend-path/shared/stages_test.go`: 17 самостоятельных тестов этапов 01–07, включая четыре отдельных сценария политики повторов. Пакет `jobs_test` импортирует публичный пакет `jobs`; тесты не обращаются к полям App, не требуют определённой внутренней очереди и не задают собственную схему снимка. Восстановление проверяется через копию файла, записанного реальным приложением. Три незавершённых задания восстанавливаются при одном обработчике и вместимости живой очереди один: New не должен ждать пользовательскую обработку или терять ранее принятую работу.

Обработчики в тестах остановлены управляемыми каналами или контекстом, HTTP-клиент ограничен таймаутом две секунды. Ожидание статуса, создания приложения и Shutdown имеет отдельные пределы. Тестовые серверы закрываются, остановка приложения выполняется при очистке. Таймаут служит пределом ожидания, не измерением скорости реализации.

Для эталонного модуля проверено:

```sh
go test -race ./... -count=1 -timeout=45s
go vet ./...
go build ./...
```

Свежий набор всех 17 тестов прошёл с race detector. Первоначальный набор до реализации был запущен агентом реализации на заготовке: получены ожидаемые провалы чистой функции, HTTP с 501 и проверки повреждённого снимка. После реализации проведён независимый запуск. Финальная проверка скачиваемых архивов приведена ниже: отсутствие файлов теста нельзя считать прохождением этапа.

Нагрузочный клиент проверен на локальном `httptest`-сервере отдельным временным набором тестов. Сначала тесты провалились на пустом `run`: отсутствовали запросы/счётчики, 503 не менял код завершения, неверные параметры принимались. После реализации с `-race` прошли три проверки: смешанные 202/429 и уникальные ключи, ошибка при 503, отказ для нулевых/слишком больших параметров и внешнего URL. Клиент обращается только к localhost или loopback-IP, не следует перенаправлениям и не использует прокси среды. Каждый HTTP-запрос имеет таймаут пять секунд. Прочие ответы, 503 и сетевые ошибки дают ненулевой код; 429 — ожидаемый отказ перегруженной очереди.

### Локальный опыт с эталонным сервером

Сервер запущен с `ADDR=127.0.0.1:18080` и отдельным JSON-файлом во временной папке. Оставлены стандартные два обработчика и очередь вместимостью шестнадцать. Команда клиента:

```sh
go run tools/backend-path/shared/load.go -requests 200 -concurrency 8 -url http://127.0.0.1:18080
```

| Наблюдение | Результат этого запуска |
|---|---|
| Запросы | 200 |
| HTTP 202 / 429 / 503 | 69 / 131 / 0 |
| Прочие HTTP / сетевые ошибки | 0 / 0 |
| Время серии | 47,096 мс |
| HTTP attempt latency p50 / p95 / max | 1,717 / 2,872 / 5,115 мс |
| Скорость принятия 202 | 1465,10 в секунду серии |
| Последующий GET /metrics | done=69, failed=0, queued=0, running=0, workers=2, capacity=16 |

Клиент завершился успешно, потому что 429 считается ожидаемой перегрузкой. Число 1465,10 характеризует скорость принятия в этой короткой серии, а не производительность завершения. Готовность всех 69 принятых работ подтверждена отдельным последующим снимком метрик. Сервер остановлен после опыта; файлы пользователя не использовались. Сервер и клиент делили один компьютер, текст короткий, выборка мала; этот запуск не задаёт целевую скорость для других условий.

### Чтение восьми глав как начинающий студент

Прочитаны все `site/content/backend-path/book/01-start.mdx`–`08-defense.mdx` в порядке order. Это симуляция чтения после выполнения упражнений основ; я не выдаю её за реальный студенческий пилот. Новых препятствий уровня P1 при чтении пути не обнаружено.

| Этап | Что позволяет двигаться самостоятельно |
|---|---|
| 01. Первая функция | Архив, версия Go, папка с go.mod, файл jobs.go, отличие пакета от main, поля результата, правила внутренних пробелов и команды текущего этапа названы. Требуется собственный тест и намеренное нарушение, а не только PASS. |
| 02. HTTP | Методы, тело и статусы объяснены; есть readText с импортами и пример httptest. 202 отделён от done, пустой вход отвергается на границе API. Для curl названы второй терминал, подстановка ID и особенности PowerShell. |
| 03. Обработчики | Порог предварительных знаний указан явно. Вместимость ожидания отделена от числа работающих обработчиков; подмена Process нужна для воспроизводимых проверок. Объяснены 429, 503, дренаж и кооперативность отмены. |
| 04. Диск | Названы DataFile, рабочая папка, один процесс, JSON, временный файл, восстановление незавершённых и возможность повторной обработки. Прочность хранения не выводится только из атомарной замены. |
| 05. Повторы | Исходный вход отделён от нормализованного текста; ключ сохраняется после перезапуска. Первый вызов включён в MaxAttempts, attempts накопителен между запусками, ожидание отменяемо. |
| 06. Метрики | Поля ответа и смысл каждого счётчика заданы. События, числа состояний и скорости разделены; автор не предлагает искать причину по одной метрике. |
| 07. Нагрузка | Клиент имеет конечное число запросов; глава не обещает обязательный 429 при любом запуске. Приём и выполнение измеряются отдельно. Перегрузка, копия повреждённого файла, перезапуск и остановка требуют воспроизведения и отчёта. |
| 08. Защита | README, рисунок, команды и границы перечислены. Новое требование двух клиентов не имеет готового решения: нужно самому определить справедливость при конечной работе, тест и область ключа. Старые тесты не объявлены оценкой этой части. |

Путь теперь имеет конечный учебный результат: работающий локальный сервис, проверки, опыт со сбоем, отчёт и самостоятельное изменение требований. Его длительность включает практику и чтение указанных предпосылок, а не только число минут восьми страниц. Эталон и тесты помогают проверить конкретный контракт; они не доказывают самостоятельное понимание и не заменяют объяснение решения.

### Проверка скачиваемых архивов

Проверены архивы из `site/web/public/downloads`, извлечённые в новые временные папки. Каждый содержит семь файлов, включая README, STAGES, исходники сервера и клиента, go.mod и тесты этапов. Команды выполнялись внутри извлечённого проекта, без зависимости от рабочего репозитория.

| Архив | Проверка | Результат |
|---|---|---|
| backend-path-starter.zip | `go build ./...` | PASS: заготовка компилируется |
| backend-path-starter.zip | `go test ./... -run '^TestStage01' -count=1 -timeout=45s` | Ожидаемый FAIL: Analyze возвращает пустой результат; сообщение показывает вход и требуемые Text/Words |
| backend-path-starter.zip | `go test ./... -run '^TestStage' -count=1 -timeout=45s` | Ожидаемый FAIL всех 17 тестов: функция ещё не реализована, HTTP возвращает объяснение заготовки с 501, повреждённый снимок ошибочно принимается |
| backend-path-reference.zip | `go test -race ./... -count=1 -timeout=45s` | PASS всех 17 тестов |
| backend-path-reference.zip | `go vet ./...` и `go build ./...` | PASS |

Негативная проверка заготовки выявила слабое условие теста файлового сбоя: постоянный HTTP 501 удовлетворял требованию «5xx». Исправление требует сначала успешно принять и завершить задание, затем нарушает доступ к файлу и проверяет отказ. После повторной упаковки этот тест ожидаемо проваливается на starter и проходит на reference. Таким образом, заглушка больше не выдаёт ложный PASS этого этапа.
