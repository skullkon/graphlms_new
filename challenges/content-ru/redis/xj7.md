На этом этапе вы добавите ненулевое время ожидания для `BLPOP`.

### `BLPOP` с ненулевым временем ожидания

Команда `BLPOP` принимает время ожидания в секундах.

```bash
$ redis-cli BLPOP list_key 0.5
# (Blocks for 0.5 seconds)
```

Если за это время элемент в списке не появился, сервер возвращает [нулевой массив](https://redis.io/docs/latest/develop/reference/protocol-spec/#null-arrays) (`*-1\r\n`). Если элемент добавлен до истечения времени, команда разблокируется и возвращает ключ списка и извлечённый элемент как массив RESP, как на предыдущих этапах.

### Тесты

Тестирующая программа запустит вашу программу так:

```
./your_program.sh
```

Затем отправит `BLPOP` с ненулевым временем ожидания:

```bash
$ redis-cli BLPOP list_key 0.1
# (Blocks for 0.1 seconds)
```

После истечения времени ожидается [нулевой массив](https://redis.io/docs/latest/develop/reference/protocol-spec/#null-arrays) (`*-1\r\n`).

Тест также проверит добавление элемента до истечения времени. В этом случае ответ — массив RESP вида `["list_key", "foo"]`, где `foo` — добавленный элемент.
