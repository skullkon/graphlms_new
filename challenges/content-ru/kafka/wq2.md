На этом этапе вы реализуете ответ `DescribeTopicPartitions` для нескольких топиков.

### Обработка нескольких топиков

Ранее вы возвращали метаданные одного топика. Теперь будете обрабатывать запросы сразу о нескольких топиках.

Запрос `DescribeTopicPartitions` может содержать несколько имён в массиве `topics`. Массив `topics` ответа должен включать соответствующую запись для каждого запрошенного топика.

Топики в ответе должны быть **отсортированы по имени в алфавитном порядке**. Это обеспечивает постоянный порядок независимо от порядка в запросе клиента.

Например, если клиент запрашивает `"zebra"` и `"apple"`, в ответе сначала должен идти `"apple"`, затем `"zebra"`.

### Тесты

Тестирующая система запустит вашу программу следующим образом:

```bash
$ ./your_program.sh /tmp/server.properties
```

Затем отправит запрос `DescribeTopicPartitions` (v0) с двумя именами топиков. У каждого топика будет один или два раздела.

Она проверит, что:

- Поле `message_size` правильно отражает размер заголовка и тела.
- Идентификатор корреляции в заголовке ответа совпадает с идентификатором в заголовке запроса.
- Топики отсортированы по имени в алфавитном порядке.
- Каждая запись топика содержит `error_code`, равное `0` (нет ошибки).
- Каждое значение `topic_name` совпадает с одним из запрошенных топиков.
- Каждое значение `topic_id` совпадает с настоящим UUID из метаданных кластера.
- Массив `partitions` каждого топика содержит правильные записи разделов.
- Все записи разделов содержат `error_code`, равное `0` (нет ошибки).
- Каждое значение `partition_index` совпадает с настоящим идентификатором раздела из метаданных.
- Значение `next_cursor` равно `-1` (null).

### Примечания

- Топики в ответе должны быть отсортированы по имени в алфавитном порядке.
- Каждый топик запроса получает полную отдельную запись в массиве `topics` ответа.
- Полная схема ответа приведена в [официальной документации `DescribeTopicPartitions`](https://kafka.apache.org/42/design/protocol/#The_Messages_DescribeTopicPartitions).
