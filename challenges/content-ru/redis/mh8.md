На этом этапе вы реализуете `EXEC` и отмену транзакций.

### Напоминание о транзакциях Redis

[Транзакции Redis](https://redis.io/docs/latest/develop/using-commands/transactions/) позволяют выполнять несколько команд как одну операцию. Основная последовательность:

1. `MULTI` — перейти в режим транзакции (реализовано ранее).
2. `SET key value`, `INCR counter` и другие — поставить команды в очередь.
3. `EXEC` — выполнить все команды очереди.

Сейчас вы реализуете `EXEC` и отмену транзакций, если их отслеживаемые ключи изменились.

### Команда `EXEC`

Команда [`EXEC`](https://redis.io/docs/latest/commands/exec/) выполняет все команды, поставленные в очередь после `MULTI`:

```bash
$ redis-cli
> SET foo 100
OK
> MULTI
OK
> SET foo 200
QUEUED
> SET bar 300
QUEUED
> EXEC
1) OK
2) OK
```

Ответ — массив RESP, каждый элемент которого содержит результат команды в порядке постановки в очередь.

### Отмена транзакций с `WATCH`

Если соединение отслеживает ключи, `EXEC` должна проверить, не изменил ли другой клиент любой из них между `WATCH` и `EXEC`. Если изменил, транзакция отменяется:

```
Client A: WATCH foo             # Server tracks "foo" for Client A
Client A: MULTI
Client A: SET bar 300           # Queued
Client B: SET foo 999           # Modifies Client A's watched key
Client A: EXEC                  # Returns *-1\r\n, queued commands discarded
```

`EXEC` возвращает нулевой массив RESP (`*-1\r\n`), а команды очереди удаляются без выполнения.

Если отслеживаемые ключи не изменились, `EXEC` выполняет транзакцию обычным образом.

### Тесты

Тестирующая программа запустит вашу программу так:

```bash
$ ./your_program.sh
```

Она создаст четырёх клиентов и выполнит два сценария.

В первом другой клиент изменяет отслеживаемый ключ:

```bash
# Client 1
> SET foo 100        # → +OK
> SET bar 200        # → +OK
> WATCH foo          # → +OK
> MULTI              # → +OK
> SET bar 300        # → +QUEUED

# Client 2 modifies the watched key
> SET foo 200        # → +OK

# Client 1 tries to execute
> EXEC               # → *-1\r\n (null array, transaction aborted)
> GET bar            # → "200" (unchanged, SET bar 300 was never executed)
```

Во втором изменяется другой, неотслеживаемый ключ:

```bash
# Client 3
> SET baz 100        # → +OK
> SET caz 200        # → +OK
> WATCH baz          # → +OK
> MULTI              # → +OK
> SET caz 400        # → +QUEUED

# Client 4 modifies a different key (not the watched one)
> SET caz 300        # → +OK

# Client 3 executes successfully
> EXEC               # → array of responses (baz was not modified)

# Client 4 verifies the transaction's write took effect
> GET caz            # → "400"
```

Будет проверено, что:

- `EXEC` возвращает нулевой массив RESP (`*-1\r\n`), если другой клиент изменил отслеживаемый ключ.
- `EXEC` возвращает массив результатов команд, если отслеживаемые ключи не менялись.
- При отмене транзакции команды очереди не выполняются, исходные значения сохраняются.
- Если отслеживаемые ключи не менялись, команды выполняются и их записи вступают в силу.

### Примечания

- Недостаточно сравнить значение ключа в момент `WATCH` и `EXEC`. Если ключ изменили, а потом вернули исходное значение, транзакция всё равно должна отмениться. Отслеживайте факт записи в ключ, а не итоговое отличие значения.
- После `EXEC` очищайте состояние наблюдения соединения — ключи и флаг dirty — независимо от успеха или отмены транзакции.
