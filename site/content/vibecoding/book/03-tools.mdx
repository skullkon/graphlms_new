## Один запрос, разные возможности

Обычный чат может предложить код. Агент в папке проекта способен прочитать существующие файлы и выполнить команды, если окружение это разрешает. Поэтому вопрос «какую модель выбрать?» не объясняет весь процесс разработки. Результат зависит также от инструментов, контекста и доступов.

Claude Code и Codex — два семейства инструментов для работы с кодирующими агентами. Для упражнений достаточно одного. Не нужно покупать два доступа ради прохождения курса. Выбирайте вариант, которым можете пользоваться в своей среде; интерфейсы и условия доступа меняются.

В CLI работа идёт в терминале; расширение редактора показывает агенту проект внутри редактора; настольное приложение предоставляет собственное рабочее окружение. Доступные действия зависят от конкретного режима. Не считайте, что облачная сессия автоматически видит все файлы на вашем компьютере.

## Из каких частей состоит работа

| Часть | Что делает | Пример в нашем проекте |
|---|---|---|
| Модель | Предлагает следующий ответ или действие | Выбирает способ добавить задачу |
| Агент и его рантайм | Выполняют цикл работы с инструментами | Читают app.py, запускают тесты |
| Инструкции проекта | Задают постоянные договорённости | Сохранять данные при ошибке |
| Скилл | Описывает повторяемую процедуру | Проверять небольшое изменение |
| MCP-сервер | Предоставляет внешние инструменты или контекст | Доступ к документации |
| Хук | Обрабатывает событие окружения | Запускает проверку перед выбранным действием |
| Git | Сохраняет историю выбранных изменений | Показывает diff перед коммитом |

Термины пока нужны для ориентации. Скиллы, MCP и харнесс разберём отдельно на практических примерах. Плагин может упаковывать несколько таких частей, но сам факт установки плагина не доказывает, что он нужен проекту.

## Первый разговор с агентом

Установку и вход выполняйте по [официальному quickstart Claude Code](https://code.claude.com/docs/en/quickstart) или [документации Codex CLI](https://learn.chatgpt.com/docs/codex/cli). Не копируйте случайную команду установки из чужого обсуждения. Курс не фиксирует тарифы и имена моделей: они не нужны для понимания процесса.

Откройте агенту только учебную папку и отправьте:

```text
Прочитай README.md, app.py и tests/test_app.py.
Пока не меняй файлы. Объясни, что уже работает,
что оставлено заготовкой и как проверить результат.
Укажи команды и ожидаемые коды возврата.
```

Сверьте ответ с файлами. Если агент заявляет, что реализовано добавление, найдите соответствующую функцию: в заготовке она сообщает о незавершённой реализации. Это первый опыт проверки ответа без самостоятельного написания кода.

## Права — часть настройки

Чтение учебной папки, редактирование кода, запуск команд и отправка данных в интернет — разные действия. Уточните, какие из них доступны выбранному агенту. Не отключайте все ограничения ради первого опыта. Текстовая инструкция «не трогай соседние папки» полезна, но реальную границу доступа задаёт окружение.

## Самостоятельное задание

Составьте карту своей среды: название клиента, способ запуска, папка проекта, доступные инструменты и действия, требующие подтверждения. Проверьте одну команду, которую предложил агент, вручную.

## Критерии и разбор

Вы различаете предложение команды и её выполнение. Можете объяснить, почему модель без файлов проекта не знает текущую реализацию. Если среда не позволяет выполнять команды, запускайте их самостоятельно и передавайте агенту сокращённый вывод; не приписывайте ему несуществующие инструменты.
