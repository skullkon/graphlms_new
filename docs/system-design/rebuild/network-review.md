# Независимая проверка сетевого блока

Проверено 2026-09-30: core `02-http`, `04-capacity`, `05-load`, `10-realtime`, `11-media`; deep `network-foundations`, `transport-proxies`, `overload`. Проверяющий работал над data/distributed блоком и не редактировал эти файлы.

Блокирующих технических ошибок и обязательных исправлений в просмотренном материале не найдено. Утверждения отделяют DNS-кэш от срока соединения, TCP ACK от commit, HTTP/2 multiplexing от TCP HOL, QUIC от прикладных зависимостей, TLS termination от сквозной защиты, request hit ratio от byte hit ratio, timeout от неизвестного исхода. Не найдено обещаний получить свежую реплику через heartbeat или отменить SQL прекращением клиентского ожидания.

Расчёты независимо проверены: BDP 100 Мбит/с × 80 мс ≈ 1 MB; 64 KB / 80 ms ≈ 6,4 Мбит/с в десятичных единицах; 5000 × 64 KiB = 312,5 MiB; поток 2 KiB/с заполнит 64 KiB за 32 с; CDN hits 0,9 MB / 100,9 MB ≈ 0,89%. M/M/1 W при μ=100 и λ=50/80/90 равен 20/50/100 ms, L при λ=80 — 4. Ограничения моделей и выбранные единицы подписаны.

Python-примеры извлечены непосредственно из Markdown и выполнены на Python 3.9.6 без пакетов. `04-capacity`: mean 20,1/49,9/101,5 ms; p99 93,0/220,9/447,5 ms. Соответствует описанной тенденции, без требования тождества выборки теории. `overload`: в обоих режимах offered=640; без лимита rejected=0, expired=83, completed=557, useful=525, peak=43; с лимитом 20 rejected=73, expired=30, completed=537, useful=508, peak=20. Баланс выполняется. Текст корректно не обещает, что меньшая очередь автоматически даст больше useful.

Маршруты новых deep существуют. Deep prerequisite refs `network-foundations` и `transport-proxies` требуют HTTP/основы и не создают цикла. В общем текущем наборе 32 core+deep граф проверен отдельно: отсутствующих ссылок и циклов нет для прочитанных prerequisite lists. Core главы сохранили последовательность; отсутствие явного `prerequisites` в части core не интерпретировалось как техническая ошибка, поскольку действующий маршрут идёт по порядку глав.

Предел проверки: не выполнялись внешние DNS/TLS/CDN-пробы, browser SSE reconnect, TCP fault injection и команды условных localhost endpoints. Они описаны как опыты при наличии собственного endpoint; текст явно предупреждает, что отсутствие такого endpoint не является измеренным отказом. Общий content-check дошёл до проверки manifest и сообщил ожидаемые content/hash/version расхождения во время параллельной пересборки; регенерация manifest относится к интеграции root.
