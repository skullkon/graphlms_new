На этом этапе вы добавите запуск сервера Redis на произвольном порту.

### Репликация с ведущим и ведомыми

[Репликация с ведущим и ведомыми](https://redis.io/docs/latest/operate/oss_and_stack/management/replication/) — схема, в которой один сервер («ведущий», master) обрабатывает все операции записи, а один или несколько серверов («реплики») поддерживают копии его данных. Когда ведущий меняет данные, он автоматически передаёт изменения репликам. Это обеспечивает избыточность данных и повышает производительность чтения.

### Поддержка произвольного порта

Для репликации нужно одновременно запускать несколько серверов Redis, каждому из которых нужен собственный порт. Поэтому сервер должен уметь запускаться на порту, отличном от стандартного `6379`.

Флаг `--port` передаёт номер порта серверу Redis:

```bash
./your_program.sh --port <port_number>
```

Сервер разбирает аргумент и запускает TCP-сервер на указанном порту.

Если флаг `--port` не задан, используется порт `6379`.

### Тесты

Тестирующая программа запустит вашу программу так:

```
./your_program.sh --port 6380
```

Затем попытается подключиться к TCP-серверу на указанном порту. Если подключение успешно, этап пройден.

### Примечания

- Тест передаст случайный номер порта, поэтому нельзя жёстко задать номер из примера.
- Если репозиторий создан до 5 октября 2023 года, скрипт `./your_program.sh` может не передавать аргументы программе. Исправьте `./your_program.sh`; подробности — в [этом PR](https://github.com/codecrafters-io/build-your-own-redis/pull/89/files).
