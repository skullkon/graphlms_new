На этом этапе вы добавите поддержку обнаружения и обработки синтаксических ошибок в пользовательских функциях в свой интерпретатор Lox.

### Ссылка на книгу

Код для этого этапа реализован в [разделе 10.3: Объявления функций](https://craftinginterpreters.com/functions.html#function-declarations).

### Проверки

Тестирующая система выполнит серию проверок с файлами `test.lox`, содержащими программы с пользовательскими функциями с аргументами.

Например, если `test.lox` содержит следующее

```
clock(;
```

Тестирующая система запустит вашу программу следующим образом:

```
$ ./your_program.sh run test.lox
[line 2] Error at ';': Expect expression.
```

Тестирующая система выполнит несколько таких проверок со случайными выражениями, например:

Тестовый случай 1:

Входные данные:

```
print clock(;
```

Ожидаемый вывод:

```
[line 1] Error at ';': Expect expression.
```

Тестовый случай 2:

Входные данные:

```
print clock)));
```

Ожидаемый вывод:

```
[line 1] Error at ')': Expect ';' after value.
```

Тестовый случай 3:

Входные данные:

```
fun f() 74;
print f();
```

Ожидаемый вывод:

```
[line 2] Error at '74': Expect '{' before function body.
```

Тестовый случай 4:

Входные данные:

```
fun foo(a, b c, d, e, f) {}
foo();
```

Ожидаемый вывод:

```
[line 2] Error at 'c': Expect ')' after parameters.
```

Тестирующая система проверит, что при ошибке компиляции код завершения вашей программы равен 65.

### Примечания

- Этот формат вывода соответствует спецификации в [репозитории книги](https://github.com/munificent/craftinginterpreters/blob/4a840f70f69c6ddd17cfef4f6964f8e1bcd8c3d4/test/function/body_must_be_block.lox)
- Сообщения об ошибках следует выводить в `stderr`, а не в `stdout`.
- На этом этапе тестирующая система не проверяет точный текст ошибки, а только завершение программы с кодом 65.
