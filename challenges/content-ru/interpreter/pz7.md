На этом этапе вы добавите поддержку обнаружения недопустимых повторных объявлений переменных в одной области видимости. Это означает выявление случаев, когда переменная объявляется несколько раз в одной локальной области видимости.

### Ссылка на книгу

Код для этого этапа реализован в [разделе 11.3: Класс разрешения имён](https://craftinginterpreters.com/resolving-and-binding.html#a-resolver-class).

### Проверки

Тестирующая система выполнит серию проверок с файлами `test.lox`, содержащими программы с повторными объявлениями переменных.

Например, если `test.lox` содержит следующее:

```
{
  var a = "value";
  var a = "other";
}
```

Тестирующая система запустит вашу программу следующим образом:

```
$ ./your_program.sh run test.lox
[line 3] Error at 'a': Already a variable with this name in this scope.
```

Тестирующая система выполнит несколько таких проверок со случайными выражениями, например:

Тестовый случай 1:

Входные данные:

```
fun foo(a) {
  var a;
}
```

Ожидаемый вывод:

```
[line 2] Error at 'a': Already a variable with this name in this scope.
```

Тестовый случай 2:

Входные данные:

```
fun foo(arg, arg) {
  "body";
}
```

Ожидаемый вывод:

```
[line 1] Error at 'arg': Already a variable with this name in this scope.
```

Тестовый случай 3:

Входные данные:

```
var a = "1";
print a;

var a;
print a;

var a = "2";
print a;

{
  var a = "1";
  var a = "2";
  print a;
}
```

Ожидаемый вывод:

```
[line 12] Error at 'a': Already a variable with this name in this scope.
```

Тестирующая система проверит, что при допустимом глобальном повторном объявлении код завершения равен 0. При недопустимом локальном повторном объявлении программа должна завершиться с кодом 65 и вывести соответствующее сообщение об ошибке.

### Примечания

- Этот формат вывода соответствует спецификации в [репозитории книги](https://github.com/munificent/craftinginterpreters/blob/4a840f70f69c6ddd17cfef4f6964f8e1bcd8c3d4/test/variable/duplicate_local.lox)
- Повторное объявление переменных разрешено в глобальной области видимости, но не в локальных
- Ошибка должна обнаруживаться во время компиляции, а не выполнения
- Сообщения об ошибках следует выводить в stderr, но их точный текст не проверяется.
