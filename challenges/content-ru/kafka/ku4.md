На этом этапе вы реализуете ответ `DescribeTopicPartitions` для топика с несколькими разделами.

### Обработка нескольких разделов

Если у топика несколько разделов, каждому соответствует отдельная запись в массиве `partitions`. Структура [записи раздела](https://binspec.org/kafka-describe-topic-partitions-response-v0?highlight=38-65) остаётся такой же, как на предыдущих этапах.

На этом этапе вы вернёте метаданные топика с двумя разделами. Для каждого нужна отдельная запись с правильным `partition_index`.

### Тесты

Тестирующая система запустит вашу программу следующим образом:

```bash
$ ./your_program.sh /tmp/server.properties
```

Затем отправит запрос `DescribeTopicPartitions` (v0) для топика с двумя разделами.

Она проверит, что:

- Поле `message_size` правильно отражает размер заголовка и тела.
- Идентификатор корреляции в заголовке ответа совпадает с идентификатором в заголовке запроса.
- Поле `error_code` записи топика равно `0` (нет ошибки).
- Ответ является корректным ответом `DescribeTopicPartitions` (v0).
- Поле `topic_name` совпадает с именем топика из запроса.
- Поле `topic_id` совпадает с настоящим UUID из метаданных кластера.
- Массив `partitions` содержит ровно две записи разделов.
- Обе записи разделов содержат `error_code`, равное `0` (нет ошибки).
- Каждое значение `partition_index` совпадает с настоящим идентификатором раздела из метаданных.
- Значение `next_cursor` равно `-1` (null).

### Примечания

- Каждому разделу нужна полная отдельная запись в массиве `partitions` с правильным `partition_index`.
- Полная схема ответа приведена в [официальной документации `DescribeTopicPartitions`](https://kafka.apache.org/42/design/protocol/#The_Messages_DescribeTopicPartitions).
