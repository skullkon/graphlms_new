На этом этапе вы добавите бессрочное блокирующее ожидание в `XREAD`.

### Бессрочное ожидание в `XREAD`

Напомним, что `XREAD` поддерживает блокировку через параметр `BLOCK <milliseconds>`.

Если `milliseconds` равен `0`, `XREAD` блокируется бессрочно, пока в поток или потоки не будет добавлена новая запись.

Рассмотрим двух отдельных клиентов. Первый отправляет блокирующую `XREAD`, указав время `0`:

```bash
$ redis-cli XREAD BLOCK 0 streams some_key 1526985054069-0
```

Этот клиент останется заблокированным до появления новой записи.

Если второй клиент в любой момент добавит запись в поток:

```bash
$ other-redis-cli XADD some_key 1526985054079-0 temperature 37 humidity 94
"1526985054079-0"
```

Команда `XREAD` первого клиента сразу разблокируется и вернёт новую запись:

```bash
1) 1) "some_key"
   2) 1) 1) 1526985054079-0
         2) 1) temperature
            2) 37
            3) humidity
            4) 94
```

### Тесты

Тестирующая программа запустит вашу программу так:

```bash
$ ./your_program.sh
```

Затем добавит запись в поток.

```bash
$ redis-cli XADD stream_key 0-1 temperature 96
```

После этого отправит серверу `XREAD` с бессрочным ожиданием:

```bash
$ redis-cli XREAD BLOCK 0 streams stream_key 0-1
```

Тест подождёт `1000` миллисекунд, чтобы убедиться, что клиент остаётся заблокированным и не завершается по тайм-ауту. Затем добавит ещё одну запись:

```bash
$ redis-cli XADD stream_key 0-2 temperature 95
```

Сервер должен вернуть следующий массив RESP:

```json
[
  [
    "stream_key",
    [
      [
        "0-2",
        [
          "temperature",
          "95"
        ]
      ]
    ]
  ]
]
```
