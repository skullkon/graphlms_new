На этом этапе мы разберём раздел вопросов DNS, в котором последовательности меток сжаты. Вы получите несколько вопросов и должны разобрать их, а затем вернуть такой же раздел вопросов (сжатие не требуется) вместе с ответами. В разделе ответов верните запись типа `A` для каждого вопроса. Значения этих записей A можно выбрать произвольно.

Поскольку структура разделов вопросов и ответов уже известна из предыдущих этапов, здесь мы приведём только общее описание входящего пакета и ожидаемого ответа.

Тестирующая система отправит следующий пакет:

```
| ------------------------------------------ |
| Header                                     |
| ------------------------------------------ |
| Question 1 (un-compressed label sequence)  |
| ------------------------------------------ |
| Question 2 (compressed label sequence)     |
| ------------------------------------------ |
```

В ответ тестирующая система ожидает:

```
| ------------------------------------------ |
| Header                                     |
| ------------------------------------------ |
| Question 1 (un-compressed label sequence)  |
| ------------------------------------------ |
| Question 2 (un-compressed label sequence)  |
| ------------------------------------------ |
| Answer 1 (un-compressed label sequence)    |
| ------------------------------------------ |
| Answer 2 (un-compressed label sequence)    |
| ------------------------------------------ |
```

Сжимать ответ не требуется. Мы никогда не попросим сделать что-либо, что приведёт к превышению ограничения на размер UDP-буфера, поэтому о сжатии ответного пакета можно не беспокоиться. Если же хочется дополнительной сложности, можете сжимать DNS-пакет: тестирующая система поддерживает и такой вариант.

Тип вопроса всегда будет `A`, а класс — `IN`.

Механизм сжатия описан в [этом разделе](https://www.rfc-editor.org/rfc/rfc1035#section-4.1.4) RFC.
