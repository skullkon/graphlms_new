На этом этапе вы обработаете скрипты дополнения, возвращающие несколько вариантов.

### Несколько вариантов

Скрипт дополнения может вернуть несколько вариантов, выводя каждый на отдельной строке в stdout.

Например, если скрипт дополнения выводит:

```
add
commit
push
```

И пользователь дважды нажимает TAB:

```bash
$ git <TAB><TAB>
add  commit  push
$ git 
```

1. Первое нажатие TAB должно вызвать звуковой сигнал терминала (поскольку единственного варианта дополнения нет).
2. Второе нажатие TAB должно показать все варианты на следующей строке в алфавитном порядке, разделив их хотя бы одним пробелом (для удобства чтения рекомендуется два).

После отображения вариантов оболочка должна снова вывести приглашение с исходным вводом.

### Проверки

Тестирующая система запустит вашу программу следующим образом:

```bash
$ ./your_program.sh
```

Затем система зарегистрирует скрипт дополнения, который всегда возвращает три варианта (`add`, `commit`, `push`):

```bash
$ complete -C /path/to/completer_script git
$ git <TAB><TAB>
add  commit  push
$ git 
```

Тестирующая система проверит, что:

- Первое нажатие TAB вызывает звуковой сигнал (нет единственного совпадения).
- Второе нажатие TAB показывает все варианты на одной строке, разделяя их хотя бы одним пробелом.
- Варианты отсортированы по алфавиту.
- После списка вариантов снова выводятся приглашение и исходный ввод.

- Пока не нужно реализовывать дополнение по наибольшему общему префиксу (LCP). К этому мы перейдём на следующих этапах.
