На этом этапе вы реализуете `MULTI` и запретите вызов `WATCH` внутри транзакции.

### Транзакции Redis

Ранее вы видели, как `WATCH` участвует в общей последовательности: начать следить за ключом, открыть транзакцию через `MULTI`, поставить команды в очередь и выполнить их через `EXEC`. Теперь начнём реализацию транзакций.

[Транзакции Redis](https://redis.io/docs/latest/develop/using-commands/transactions/) позволяют клиентам выполнять несколько команд как одну операцию. Основная последовательность:

1. `MULTI` — перейти в режим транзакции: команды ставятся в очередь вместо немедленного выполнения.
2. `SET key value`, `INCR counter` и другие — поставить команды в очередь.
3. `EXEC` — выполнить все команды очереди.

`EXEC` появится позже. Сейчас вы реализуете `MULTI` и проверку в `WATCH`, не вызвана ли она внутри транзакции.

### Команда `MULTI`

Команда [`MULTI`](https://redis.io/docs/latest/commands/multi/) начинает транзакцию.

```bash
$ redis-cli MULTI
OK
```

При вызове `MULTI` сервер:
1. Помечает соединение как находящееся в транзакции.
2. Возвращает `OK` простой строкой.

### Обновлённая команда `WATCH`

`WATCH` должна вызываться **до** начала транзакции. Внутри транзакции она запрещена, поскольку транзакция уже началась и команды уже помещаются в очередь.

Теперь, когда состояние транзакции хранится, `WATCH` должна соблюдать это правило:

- Если соединение вне транзакции:
    1. Добавить ключ в набор отслеживаемых ключей соединения.
    2. Вернуть `OK` простой строкой.
- Если соединение внутри транзакции (после `MULTI`):
    1. Вернуть ошибку RESP вида `-ERR WATCH inside MULTI is not allowed\r\n`. Точная формулировка может отличаться, но должна содержать `ERR`, `WATCH`, `inside MULTI` и `not allowed`.

Например:

```bash
$ redis-cli
> WATCH counter
OK
> MULTI
OK
(TX)> WATCH another_key
(error) ERR WATCH inside MULTI is not allowed
```

### Тесты

Тестирующая программа запустит вашу программу так:

```bash
$ ./your_program.sh
```

Затем создаст клиента, начнёт транзакцию через `MULTI` и отправит `WATCH` со случайным ключом:

```bash
$ redis-cli
> MULTI
OK
> WATCH key
(error) ERR WATCH inside MULTI is not allowed
```

Будет проверено, что:
- `MULTI` возвращает `OK` простой строкой.
- `WATCH` внутри транзакции возвращает ошибку RESP, содержащую `ERR`, `WATCH`, `inside MULTI` и `not allowed`.

### Примечания

- Понадобится хранить состояние отдельно для каждого соединения, например в отображении с ключом-соединением или сокетом.
- При вызове `WATCH` вне транзакции сохраняйте отслеживаемые ключи, хотя они пока не используются. Это подготовка к следующим этапам.
- Формат сообщения об ошибке может отличаться, если содержит обязательные ключевые слова.
