# Исследование структуры курса Git

Проверено 30 сентября 2026 года. Цель — первый самостоятельный курс для человека, умеющего открыть терминал и создать текстовый файл. Все обязательные лаборатории локальные, бесплатные, воспроизводимые и не требуют GitHub. Команды проверяются на Git 2.50.1; минимальная версия курса — 2.28 из-за `git init -b`. На Windows используется Git Bash, на macOS/Linux — bash или совместимый терминал.

## Что изучено и как использовано

[Оглавление Pro Git](https://git-scm.com/book/en/v2) разделяет начало работы, повседневные операции, ветвление, удалённую работу и дополнительные инструменты. Для своего курса взята постепенность: сначала локальная история, затем совместная работа. Внутренние объекты вводятся лишь настолько, чтобы объяснить снимок и ссылки. Полный серверный администрируемый стек и интеграции других VCS не входят в первый курс.

[MIT Missing Semester: Version Control](https://missing.csail.mit.edu/2020/version-control/) начинает с модели данных и связывает команды с её изменением. Адаптирован принцип: ученик прогнозирует, какую область или ссылку изменит команда, затем проверяет наблюдение. Упражнения нашего курса написаны заново: вместо внешних репозиториев — маленький локальный проект и контролируемые поломки.

[GitHub Skills: introduction](https://github.com/skills/introduction-to-github) и [review pull requests](https://github.com/skills/review-pull-requests) показывают последовательную практику ветки, изменения и обсуждения. Адаптирован цикл автор → проверяющий → доработка → интеграция. Обязательная реализация использует два клона и записку ревью; это модель взаимодействия, а не интерфейс GitHub. Настоящий PR в личном тестовом репозитории — необязательное продолжение. Во время исследования skills.github.com перенаправлял на GitHub Learn, поэтому проверены официальные репозитории Skills.

Ни тексты, ни иллюстрации, ни задания этих курсов не скопированы и не переведены. Их учебная структура помогла выбрать последовательность; объяснения, сценарии и лаборатории оригинальные. Pro Git и Missing Semester имеют лицензии с ограничениями коммерческого использования; доступность чтения не означает разрешение публиковать перевод. Ссылки сохраняют атрибуцию методических источников.

## Технические первоисточники

Для точного поведения использованы официальные руководства:

- Модель: [глоссарий в исходниках Git](https://raw.githubusercontent.com/git/git/master/Documentation/glossary-content.adoc), [ls-tree](https://git-scm.com/docs/git-ls-tree).
- Локальная запись: [init](https://git-scm.com/docs/git-init), [config](https://git-scm.com/docs/git-config), [add](https://git-scm.com/docs/git-add), [commit](https://git-scm.com/docs/git-commit).
- Наблюдение: [diff](https://git-scm.com/docs/git-diff), [log](https://git-scm.com/docs/git-log), [show](https://git-scm.com/docs/git-show).
- Ветки и обмен: [switch](https://git-scm.com/docs/git-switch), [merge](https://git-scm.com/docs/git-merge), [clone](https://git-scm.com/docs/git-clone), [fetch](https://git-scm.com/docs/git-fetch), [pull](https://git-scm.com/docs/git-pull), [push](https://git-scm.com/docs/git-push).
- Изменение и восстановление: [restore](https://git-scm.com/docs/git-restore), [reset](https://git-scm.com/docs/git-reset), [revert](https://git-scm.com/docs/git-revert), [reflog](https://git-scm.com/docs/git-reflog), [rebase](https://git-scm.com/docs/git-rebase/2.50.0), [cherry-pick](https://git-scm.com/docs/git-cherry-pick), [stash](https://git-scm.com/docs/git-stash), [bisect](https://git-scm.com/docs/git-bisect).
- Файлы: [gitignore](https://git-scm.com/docs/gitignore), [gitattributes](https://git-scm.com/docs/gitattributes), [Git LFS](https://git-lfs.com/), [GitHub: удаление чувствительных данных](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

Часть адресов документации при прямом открытии возвращала ошибку провайдера. Для init/fetch использована выдача первичного сайта; rebase проверен по доступной версии 2.50.0. Командные сценарии дополнительно проверяются установленным Git. В уроках не зависят от новых опций Git 2.56.

## Программа и учебные критерии

14 глав: модель; установка и первый коммит; diff и история; ветки; слияние и конфликт; локальный bare remote; fetch/pull/push; совместное ревью; restore/revert/reset; rebase; cherry-pick/stash; bisect; ignore/секреты/LFS; финальный проект. Каждая глава даёт сценарий, механизм, исполняемый пример во временной папке, ожидаемое наблюдение, отдельную лабораторию, критерии и разбор. minutes означает чтение, время практики указано отдельно.

Финальный проект соединяет два клона, ревью ветки, конфликт, исправление опубликованной ошибки и поиск регрессии. Готовность подтверждается состоянием репозитория, проверками файлов и объяснением графа. Ученик не обязан иметь опыт разработки: программа работает с текстовым договором учебного сервиса и shell-проверкой.

Только синтетические данные и адреса example.invalid. Нет обязательного force push, настоящих секретов, очистки чужих репозиториев или публикации во внешний проект. `tools/git-labs/smoke.sh` создаёт временную папку, изолирует пользовательские настройки и проверяет локальные сценарии. Архив лабораторий упаковывает root.

## Выполненная проверка курса

Созданы 14 глав с order 1–14. Объём без fenced-кода: 700–780 слов на главу; с командами — примерно 815–875. Проверены frontmatter, ссылки переходов, парность code fences и отсутствие raw HTML. Отдельные разделы критериев и разбора присутствуют во всех главах.

`bash tools/git-labs/smoke.sh` завершился 0: десять групп PASS, охватывающих все заявленные локальные механизмы, на Git 2.50.1 (Apple Git-155). Дополнительно извлечены и исполнены все 23 sh-блока четырнадцати глав в отдельном TMPDIR с изолированными настройками: каждый сценарий завершён ожидаемо, конфликт merge обработан как намеренный отказ. Никакие пользовательские репозитории не использовались. По окончании курса финальное изменение требований остаётся самостоятельной работой ученика, его решение smoke не оценивает.
