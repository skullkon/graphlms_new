## Повторяющийся запрос

После каждого изменения вы пишете: «Прочитай требования, проверь ошибочные случаи, запусти тесты, покажи diff». Если процедура повторяется и её условия понятны, можно сохранить её как скилл.

**Скилл** — пакет инструкций для определённой работы, иногда со скриптами и примерами. Он помогает агенту выбирать и выполнять процедуру. Скилл не добавляет права доступа сам по себе и не гарантирует соблюдение каждого шага. Если этап должен обязательно блокировать действие, нужна проверка в окружении, а не только просьба в тексте.

[Claude Code](https://code.claude.com/docs/en/skills) и [Codex](https://learn.chatgpt.com/docs/build-skills) используют файлы `SKILL.md`. Для локального проекта в Claude Code подходит `.claude/skills/review-change/SKILL.md`, в Codex — `.agents/skills/review-change/SKILL.md`. Это пути относительно корня учебного проекта. Общий формат не делает все настройки и способы вызова взаимозаменяемыми.

## Минимальный скилл проверки

В архиве есть шаблон. Скопируйте его в папку выбранного клиента и прочитайте:

```markdown
---
name: review-change
description: Проверяй небольшое изменение менеджера задач перед сохранением. Не используй для публикации.
---
Прочитай SPEC.md и посмотри изменённые файлы.
Свяжи изменение с одним требованием.
Проверь обычный сценарий, ошибочный ввод и сохранение данных.
Запусти python3 check.py и сообщи код возврата.
Посмотри git diff и git status --short.
Назови ограничения. Не меняй требования или тесты ради успеха.
Не делай commit и не отправляй изменения без запроса человека.
```

`name` даёт имя, `description` объясняет, когда процедура нужна. Ниже находится порядок действий. Хорошее описание отделяет проверку от исправления и публикации. Название «помощник для всего» затрудняет выбор нужной процедуры.

Для Claude Code такой скилл можно вызвать как `/review-change`, для Codex — упоминанием `$review-change`. Перед первым вызовом убедитесь, что клиент обнаружил скилл; если его нет в списке, проверьте путь и актуальную документацию. Когда результатом должна быть только проверка, уточните: «Ничего не исправляй».

## Что сохранить, а что оставить в задаче

В скилле хранится стабильная процедура. Конкретное требование «отклонять пустое название» принадлежит спецификации и тестам. Текущий путь к файлу с данными может меняться от опыта к опыту. Скилл, в который вписали все частные случаи, быстро устаревает.

Не устанавливайте десятки скиллов заранее. Сначала повторите работу вручную и найдите полезный общий порядок. После установки чужого скилла прочитайте инструкции и скрипты: пакет может содержать запускаемый код и сетевые действия.

## Самостоятельное задание

Подключите скилл в учебной папке. Попросите проверить изменение без исправлений. Затем дайте заведомо неполную задачу: «Проверь приложение». Посмотрите, запрашивает ли агент область проверки или честно указывает, что проверил.

## Критерии и разбор

Вы можете объяснить, почему скилл был выбран, какие шаги реально выполнены и что осталось без проверки. Отчёт должен ссылаться на команды и случаи. Фраза «использовал скилл» описывает процедуру, но ещё не доказывает качество результата. Сравните отчёт с исходной инструкцией.
