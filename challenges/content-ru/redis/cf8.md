На этом этапе вы добавите отправку пустого файла RDB ведущим сервером.

### Полная повторная синхронизация

При первом подключении реплика отправляет ведущему `PSYNC ? -1`, сообщая, что у неё ещё нет данных и требуется полная повторная синхронизация.

Ведущий отвечает в два шага:

- Подтверждает запрос ответом `FULLRESYNC` (реализовано ранее).
- Отправляет снимок текущего состояния как [файл RDB](https://rdb.fnordig.de/file_format.html).

Реплика должна загрузить файл в память и заменить своё состояние данными ведущего.

В этом задании не нужно самостоятельно формировать RDB. Можно использовать заранее заданный пустой файл RDB: будем считать, что база ведущего всегда пуста.

Шестнадцатеричное представление и base64 пустого файла RDB находятся [здесь](https://github.com/codecrafters-io/redis-tester/blob/main/internal/assets/empty_rdb_hex.md). Перед отправкой реплике их нужно декодировать в двоичные данные.

Файл отправляется в формате:

```
$<length_of_file>\r\n<binary_contents_of_file>
```

Это похоже на кодирование [объёмных строк](https://redis.io/topics/protocol#resp-bulk-strings), но **без завершающего `\r\n`**.

### Тесты

Тестирующая программа запустит вашу программу так:

```
./your_program.sh --port <PORT>
```

Затем подключится к TCP-серверу как реплика и выполнит команды:

1. `PING` — ожидается `+PONG\r\n`.
2. `REPLCONF listening-port <PORT>` — ожидается `+OK\r\n`.
3. `REPLCONF capa eof capa psync2` — ожидается `+OK\r\n`.
4. `PSYNC ? -1` — ожидается `+FULLRESYNC <REPL_ID> 0\r\n`.

После последнего ответа тест ожидает пустой файл RDB от сервера.

Подойдёт любой корректный пустой файл RDB.

### Примечания

- Файл RDB отправляется так: `$<length>\r\n<contents>`.
  - `<length>` — длина файла в байтах.
  - `<contents>` — двоичное содержимое файла.
  - Это НЕ объёмная строка RESP: в конце нет `\r\n`.
- Подробнее о формате RDB — в [этой статье](https://rdb.fnordig.de/file_format.html). В задании есть отдельное расширение, посвящённое чтению файлов RDB.
