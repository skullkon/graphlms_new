На этом этапе вы добавите поддержку получения ответного сообщения рукопожатия расширений.

### Рукопожатие расширений: часть 2

На предыдущем этапе ваш клиент отправлял другому пиру сообщение рукопожатия расширений. Теперь вы добавите получение ответного сообщения от пира.

Его структура будет такой же, как у сообщения, отправленного на предыдущем этапе. Словарь полезной нагрузки содержит следующие ключи: `{"m": {"ut_metadata": <PEER'S ID>}}`.

Программа должна сохранить идентификатор расширения `ut_metadata` и вывести его. На следующих этапах он понадобится для отправки сообщений расширения `ut_metadata`.

Напомним общую последовательность действий:

- Установить TCP-соединение с пиром.
- Отправить сообщение базового рукопожатия.
- Получить сообщение базового рукопожатия.
- Отправить сообщение битового поля (в этом задании можно пропустить).
- Получить сообщение битового поля.
- Если пир поддерживает расширения (судя по зарезервированному биту базового рукопожатия):
  - Отправить сообщение рукопожатия расширений (предыдущий этап).
  - Получить сообщение рукопожатия расширений (**этот этап**).

### Тесты

Тестирующая система запустит вашу программу следующим образом:

```bash
$ ./your_program.sh magnet_handshake <magnet-link>
```

Ожидаемый вывод:

```
Peer ID: 0102030405060708090a0b0c0d0e0f1011121314
Peer Metadata Extension ID: 123
```

Значение `Peer Metadata Extension ID` генерируется случайно; его нужно извлечь из словаря сообщения рукопожатия расширений.

### Примечания

- Для локальной проверки можно использовать [эти magnet-ссылки](https://github.com/codecrafters-io/bittorrent-test-seeder/blob/main/torrent_files/magnet_links.txt). Возможно, потребуется заключить ссылки в двойные кавычки, чтобы экранировать специальные символы в терминале.
- Идентификаторы расширений нужно хранить отдельно для каждого пира: разные пиры могут использовать разные идентификаторы одного расширения.
