На этом этапе вы добавите поддержку обработки ошибок времени выполнения при вычислении операторов отношения `>`, `<`, `>=` и `<=`.

### Ссылка на книгу

Код для этого этапа реализован в [разделе 7.3: Ошибки времени выполнения](https://craftinginterpreters.com/evaluating-expressions.html#runtime-errors).

### Проверки

Тестирующая система проверит вашу программу с помощью файла `test.lox`, содержащего выражение с оператором отношения `>`, `<`, `>=` или `<=`. Это выражение
будет содержать использование оператора отношения, которое должно вызвать ошибку времени выполнения.

Операторы отношения `>`, `<`, `>=` и `<=` вызывают ошибку времени выполнения, если операнды не являются числами.

Например, если `test.lox` содержит следующее:

```
17 > "bar"
```

Тестирующая система запустит вашу программу следующим образом:

```
$ ./your_program.sh evaluate test.lox
Operands must be numbers.
[line 1]
```

Тестирующая система выполнит несколько таких проверок со случайными выражениями, например:

| Входные данные | Ожидаемый вывод |
| :---: | :-------------: |
| `"foo" < false` | `Operands must be numbers.` |
| `true < 2` | `Operands must be numbers.` |
| `("foo" + "bar") < 42` | `Operands must be numbers.` |
| `false > true` | `Operands must be numbers. `|

Тестирующая система проверит, что код завершения равен 70, что означает ошибку времени выполнения. Обратите внимание: он отличается от ожидаемого кода завершения при синтаксической ошибке — 65.

### Примечания

- Этот формат вывода соответствует спецификации в [репозитории книги](https://github.com/munificent/craftinginterpreters/blob/01e6f5b8f3e5dfa65674c2f9cf4700d73ab41cf8/test/expressions/evaluate.lox)
- Сообщения об ошибках следует выводить в `stderr`, а не в `stdout`.
- На этом этапе тестирующая система не проверяет точный текст ошибки, а только завершение программы с кодом 70.
