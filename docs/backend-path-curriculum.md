# Бесплатный путь: Go и сервис фоновых заданий

Статус: восемь глав написаны в `site/content/backend-path/book/`. Путь использует существующие главы как каноническое чтение, не меняет их порядок и не требует прохождения всего каталога. Маршрут глав — `/backend-path/book/[slug]`, точка входа — `/learn/backend`.

Ученик начинает без опыта программирования, проходит основы Go с упражнениями, затем последовательно строит один локальный сервис. Бесплатное ядро включает тексты, стартовый проект, проверки, нагрузочный клиент и эталон. Не нужны коммерческий опыт, платная подписка, облако, Docker или сторонний API. Нужны компьютер, редактор, терминал, Go 1.25 и интернет для первоначального скачивания. Время чтения не включает прохождение предшествующих курсов и практику.

## Контракт проекта

`Analyze(text)` возвращает `Result` с текстом в верхнем регистре после удаления краевых пробелов и количеством слов через `strings.Fields`. Внешних побочных эффектов нет. `Config` задаёт Workers, QueueSize, DataFile, MaxAttempts, RetryDelay и подменяемую `Process(ctx,text)`. `New(Config)` готовит приложение, `Handler` обслуживает HTTP, `Shutdown(ctx)` закрывает приём и ожидает завершения.

POST получает `{"text":"hello go"}`. Ответ 202 содержит id, text, status, result, attempts, error. GET читает запись или отвечает 404. Статусы: queued/running/done/failed. Полный приём отвечает 429, остановка — 503. Идентификатор клиента появится только как самостоятельное изменение требований в восьмой главе.

Ключ идемпотентности необязателен; он сравнивается с исходным `body.text` до trim. В записи `job.text` хранится обрезанный текст, а исходный вход для сравнения ключа сохраняется отдельно. Совпавшие ключ и вход возвращают прежний id, конфликт — 409, в том числе после перезапуска. Проверка и создание согласованы для конкурентных запросов.

ErrRetryable определяется через `errors.Is`. MaxAttempts ограничивает один цикл обработки (по умолчанию три запуска), а `attempts` записи накоплен между перезапусками. Восстановление само по себе не увеличивает счётчик; новая реально начатая попытка увеличивает его. После сбоя новый цикл может дать накопленное значение больше трёх: это явно допустимая повторная обработка.

JSON-файл принадлежит одному процессу. queued/running восстанавливаются в ожидание. Восстановленный конечный backlog ранее принятых заданий может превышать live QueueSize, потому что включает задания, которые были running перед сбоем; новый приём при заполнении отклоняется. Метрика queued отражает общее ожидание, capacity — предел живой очереди. Архив не обещает ровно один внешний эффект и не доказывает долговечность при любой потере питания.

`GET /healthz` отражает готовность 200/503. `GET /metrics` отдаёт JSON queued/running/done/failed/retries/workers/capacity. Значение и временная область retries должны совпасть с реализацией и README. Сервер: `go run ./cmd/server`, ADDR по умолчанию 127.0.0.1:8080, DATA_FILE jobs.json, WORKERS 2, QUEUE_SIZE 16. Клиент: `go run ./cmd/load -requests 200 -concurrency 8 -url http://127.0.0.1:8080`.

## Материалы и честная проверка

Стартовый и эталонный проекты — отдельные Go-модули в `tools/backend-path/{starter,reference}`. Архивы `/downloads/backend-path-starter.zip` и `/downloads/backend-path-reference.zip` бесплатны. Стартовые заглушки компилируются; целевые TestStage01…07 сначала падают. Команды этапа запускают текущий и уже решённые этапы, без объявления будущих FAIL ошибкой сегодняшней работы. Эталон открывают после попытки в отдельной папке. npm для ученика не нужен.

В первой главе объясняются папка с go.mod, отсутствие необходимости повторного go mod init, размещение объявлений вне main, намеренный FAIL теста и самостоятельная добавка случая. В HTTP-главе объясняются запрос/ответ, JSON, httptest и 202. В хранении — чтение байтов, JSON-декодирование, относительный путь, t.TempDir и ошибочные данные. В конкурентности — отдельный локальный -race и кооперативность отмены. Проверки не заменяют объяснение архитектуры и не гарантируют отсутствие всех гонок.

Восьмой этап не содержит готового ответа: горячий клиент A не должен бесконечно задерживать редкого B при оговорённых условиях. Ученик задаёт проверяемую гарантию, область ключей, правила приёма, восстановление и остановку, сравнивает два подхода и доказывает выбор своими тестами. В эталоне этого решения нет. Это завершение пути, а не платный следующий уровень.

## Граница завершения

Завершённый результат — работающий локальный проект, зелёные проверки ядра и race-сценариев, воспроизводимый отчёт, ясные границы и самостоятельное изменение требований. Ни восемь текстов, ни чужой эталон не гарантируют прохождение любым учеником или готовность к любой production-системе. Наблюдаемые трудности возвращают ученика к конкретному prerequisite, а не к требованию коммерческого опыта.
