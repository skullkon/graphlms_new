На этом этапе вы добавите блокирующее ожидание в `XREAD`.

### Блокирующее ожидание в `XREAD`

По умолчанию `XREAD` работает синхронно: сразу возвращает доступные записи либо пустой ответ, если записей нет.

Необязательный параметр `BLOCK` позволяет клиентам ждать появления новых данных.

Синтаксис:

```bash
XREAD BLOCK <milliseconds> STREAMS <key> <id>
```

Как это работает:
- Клиент отправляет команду и указывает время ожидания в миллисекундах.
- Если записи с идентификаторами больше указанного уже есть, команда сразу их возвращает.
- Если новых записей нет, команда блокируется и ждёт.
- Если до истечения времени в поток добавлена запись, команда разблокируется и возвращает новую запись или записи.
- Если время истекло, а новых данных нет, сервер отвечает нулевым массивом (`*-1\r\n`).

Рассмотрим двух отдельных клиентов. Первый отправляет блокирующую `XREAD`:

```bash
$ redis-cli XREAD BLOCK 1000 streams some_key 1526985054069-0
```

Теперь этот клиент заблокирован и ждёт новой записи.

Тем временем второй клиент может добавить запись в поток:

```bash
$ other-redis-cli XADD some_key 1526985054079-0 temperature 37 humidity 94
"1526985054079-0"
```

Если запись добавлена в течение `1000` миллисекунд, `XREAD` первого клиента сразу разблокируется и вернёт новую запись:

```bash
1) 1) "some_key"
   2) 1) 1) 1526985054079-0
      2) 1) temperature
         2) 37
         3) humidity
         4) 94
```

Если же до истечения времени запись не появилась, команда завершится без данных и вернёт нулевой массив:

```bash
(nil)
```

### Тесты

Тестирующая программа запустит вашу программу так:

```bash
$ ./your_program.sh
```

Затем добавит запись в поток.

```bash
$ redis-cli XADD stream_key 0-1 temperature 96
```

После этого отправит серверу `XREAD` с параметром `BLOCK`.

```bash
$ redis-cli XREAD BLOCK 1000 streams stream_key 0-1
```

Из другого экземпляра redis-cli тест добавит запись в течение `500` миллисекунд.

```bash
$ redis-cli XADD stream_key 0-2 temperature 95
```

Сервер должен ответить первому клиенту следующим массивом RESP:

```json
[
  [
    "stream_key",
    [
      [
        "0-2",
        [
          "temperature",
          "95"
        ]
      ]
    ]
  ]
]
```

Затем тест отправит ещё одну блокирующую `XREAD`, но на этот раз дождётся полного истечения времени ожидания перед проверкой ответа.

```bash
$ redis-cli XREAD block 1000 streams stream_key 0-2
```

В этом случае сервер должен вернуть [нулевой массив](https://redis.io/docs/latest/develop/reference/protocol-spec/#null-arrays) (`*-1\r\n`).
