# Оглавление учебника (сквозные главы-основы)

Линейно читаемый учебник по конкурентности Go. Каждая глава — `content/book/<slug>.mdx`
с frontmatter `{ title, slug, order, minutes }`. На главы ссылается теория задач
как `/book/<slug>`. Тон — как у задачи 01: глубоко, с кодом, с прод-контекстом.

| order | slug | Глава | Ключевое |
|------|------|-------|----------|
| 1 | `goroutines` | Горутины и планировщик | go-стек, G-M-P, дёшево ли создавать, когда блокируются |
| 2 | `memory-model` | Модель памяти и happens-before | видимость записей, зачем нужна синхронизация, data race ≠ race condition |

## Путь ученика без опыта программирования

Предпосылки: работа с браузером и текстовым редактором, арифметика и сравнение чисел. Терминал, Go, тесты и сеть объясняются в материалах; опыт промышленного backend не предполагается. Возраст не является проверкой готовности. Время во frontmatter описывает чтение; самостоятельная практика добавляет время.

1. Базовый Go: hello → variables → control-flow → functions → pointers → collections → structs → interfaces → errors. Выполнять упражнения перед «Что дальше» и сравнивать с проверкой. iota, fallthrough, именованные результаты и embedding можно перечитать позже.
2. Локальная практика: запуск с go.mod объяснён в hello; первый тест — в packages-modules. Для статичных generics-примеров сначала освоить локальный запуск. Дженерики не обязательны для начала конкурентных задач, но функции как значения, замыкания и общие данные среза обязательны.
3. Переход: упражнение sumAsync в goroutines-intro, затем текущий порядок книги concurrency. Сначала запуск и ожидание; G-M-P перечитать после каналов/select. В memory-model начать с записи/close/приёма; вернуться к списку sync/atomic после этих глав. scheduler-deep — заключительное дополнительное чтение.
4. Практика по задачам без смены id: 02 → 03 → 04 → 01; затем 05–08; после context/patterns 09–12 и 13–15; затем 16–20; ревью 22 → 21; варианты пула 24 → 28 → 29 → 30 → 27 → 31 → 25 → 26 → 23 → 32.

В каждой главе обеих книг есть самостоятельное упражнение с проверкой. В concurrency дополнительно указаны необходимые знания и разделы второго чтения. Перед сложными задачами: рекурсия объяснена в goroutines, Duration/Timer/Ticker — в select, HTTP и освобождение Body — в context, token/leaky bucket, singleflight, шардирование, последовательный BFS, очередь приоритетов, future и жизненный цикл пула — в patterns.

Критерий готовности к concurrency: ученик без готового решения пишет функцию, перебирает срез, меняет поле через указатель, проверяет error, запускает go test и объясняет, что именно ждёт приём из канала. После конкурентных изменений отдельно проверяет данные, завершение и отмену, затем выполняет go test -race. Успешный запуск не является доказательством всех возможных путей.
