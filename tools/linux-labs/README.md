# Лаборатории курса Linux

Этот бесплатный набор сопровождает 14 глав курса. Для запуска нужны Bash версии 3 или новее, Python 3, curl, tar и обычные утилиты awk, grep, cmp, find. Набор работает в Ubuntu и выполняет переносимую часть на macOS. Сам macOS не является Linux: успешный запуск здесь не подтверждает установку Ubuntu, работу APT, `/proc`, `ip`, `ss` или пользовательского systemd.

Если архив распакован в новую папку, перейдите в неё и выполните:

```bash
bash smoke.sh
```

Из корня репозитория:

```bash
bash tools/linux-labs/smoke.sh
```

Скрипт создаёт собственную временную папку, сообщает её путь и сохраняет материалы после завершения. Sudo не требуется. Пользовательские файлы не удаляются, внешний интернет не используется. HTTP-сервер слушает только `127.0.0.1`; операционная система выбирает свободный порт. Скрипт останавливает свой дочерний сервер и не посылает сигналы чужим процессам. Не запускайте от root: проверка отказа записи предназначена для обычного пользователя и в таком режиме пропускается с объяснением.

Нормальный результат — пять строк PASS и финальное сообщение о переносимых проверках. Если утилита отсутствует или ожидание не совпало, скрипт завершается с ненулевым статусом. Рабочая папка содержит входные файлы, отчёты, stderr, архив, восстановленные данные и журнал сервера: их можно осмотреть по упражнениям курса. Остановка процесса через TERM проверяет именно учебный дочерний процесс; строка `Terminated` от оболочки не означает неожиданный сбой лаборатории.

## Что проверяется

- Путь с пробелом, независимая копия, переименование, относительная символическая ссылка и поиск обычных файлов.
- Два совпадения grep и статус 1 при отсутствии совпадений.
- Отчёт: пять запросов, две ошибки 500; пустой файл; неверный формат; отсутствие файла или аргумента. Неуспех печатает диагностику и не выдаёт успешный отчёт.
- Разрешения собственного файла, окружение дочернего Bash и остановка собственного sleep.
- Архивирование, извлечение в новый каталог, сравнение содержимого и повторный отчёт.
- Локальный HTTP-ответ, код 404 и отсутствие ответа после остановки сервера.

## Файлы и ручная практика

`report.sh` дословно совпадает со скриптом десятой главы. Учебный формат журнала: две колонки, трёхзначный код и путь без пробелов. Это ограниченная модель, которая не разбирает произвольный production-журнал. В каталоге fixtures лежат корректный `requests.log` и некорректный `invalid.log`.

```bash
bash report.sh fixtures/requests.log
bash report.sh fixtures/invalid.log
printf 'status=%s\n' "$?"
```

Ожидания: первый вызов печатает `requests=5 failures=2` и возвращает 0. Второй печатает диагностику в stderr и возвращает 2. Проверяйте статус сразу после нужного вызова. Чтобы изменить данные, сначала скопируйте fixtures в собственную рабочую папку, затем добавьте строку с кодом 200 и предскажите новый счёт.

`serve.py` — помощник автоматической проверки: стандартная библиотека Python привязывает сервер к свободному loopback-порту и записывает номер порта в переданный файл. Он не является службой production, не предусматривает TLS или аутентификацию. В главах сеть исследуется вручную через обычный `python3 -m http.server`, чтобы ученик сам наблюдал запуск, порт и остановку.

Затем выполните Linux-часть курса внутри выбранной Ubuntu: подтвердите `/etc/os-release`, изучите права и процессы, проверьте диагностику `ip`/`ss`, пакеты и доступность `systemctl --user`. Для WSL без пользовательского manager в главе о службах предусмотрен ручной путь. Завершите финал восстановлением сайта и журнала в новый каталог и повторным запуском отчёта. Результат smoke не заменяет самостоятельную работу и объяснение причин трёх намеренных отказов.

## Проверка набора

2026-09-30: `bash smoke.sh` успешно выполнен на Darwin/macOS; `bash -n smoke.sh report.sh` проверяет синтаксис. Linux-специфичные команды здесь не запускались. Различия имён интерфейсов, PID, времени, временных путей и свободного порта ожидаемы. Для завершения курса не нужны платные сервисы, сертификат, отдельный сервер или регистрация в облаке.
