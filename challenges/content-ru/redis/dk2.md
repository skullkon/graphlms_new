На этом этапе вы добавите поддержку `BITOP AND` для исходных карт разной длины.

### `BITOP AND` для карт разной длины

Если исходные строки имеют разную длину, Redis считает короткие дополненными нулями до длины самой длинной. Длина результата равна длине самой длинной строки.

```bash
> SETBIT key1 1 1
(integer) 0
> SETBIT key1 10 1
(integer) 0
> SETBIT key2 1 1
(integer) 0
```

Здесь команды `SETBIT` создали две карты: `key1` равна `01000000 00100000` (2 байта), а `key2` — `01000000` (1 байт).

```bash
> BITOP AND dest key1 key2
(integer) 2
> GETBIT dest 1
(integer) 1
> GETBIT dest 10
(integer) 0
```

При операции `BITOP AND` Redis рассматривает короткую строку как дополненную нулями. В этом примере `key2` рассматривается как `01000000 00000000` — второй байт заполнен `0`.

Только бит `1` установлен в обоих ключах. Поэтому `dest` получит значение `01000000 00000000`. Команда `BITOP` вернёт `2` — длину результата.

Дополнительное правило:

- Отсутствующий ключ считается нулевой строкой длиной с самую длинную исходную строку.

### Проверки

Тестирующая система запустит программу так:

```bash
$ ./your_program.sh
```

Затем создаст две карты разной длины командами `SETBIT`.

```bash
$ redis-cli SETBIT key1 1 1
$ redis-cli SETBIT key1 10 1
$ redis-cli SETBIT key2 1 1
```

Она отправит `BITOP AND`, сохраняющую результат в новый ключ.

```bash
$ redis-cli BITOP AND dest key1 key2
```

Ожидаемый ответ — `:2\r\n`, то есть 2 в формате [целого числа RESP](https://redis.io/docs/latest/develop/reference/protocol-spec/#integers).

Далее будут отправлены команды `GETBIT` для целевого ключа.

```bash
$ redis-cli GETBIT dest 1
```

Ожидаемый ответ — `:1\r\n`.

```bash
$ redis-cli GETBIT dest 10
```

Ожидаемый ответ — `:0\r\n`.

### Примечания

- `BITOP` поддерживает и другие [операции](https://redis.io/docs/latest/commands/bitop/): `OR`, `XOR` и `NOT`. Операция `BITOP OR` появится на следующих этапах, а `XOR` и `NOT` в этой задаче не рассматриваются.
