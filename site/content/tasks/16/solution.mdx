## Идея решения

Число токенов хранится как float64. Каждый Allow под мьютексом
добавляет rps × прошедшее время, ограничивает запас ёмкостью бакета
и тратит один целый токен при наличии.

## Эталон

```go
package solution

import (
	"sync"
	"time"
)

// RateLimiter — ограничитель частоты по алгоритму token bucket.
//
// Бакет вмещает до rps токенов и пополняется со скоростью rps в секунду.
// Каждый разрешённый Allow() тратит один токен.
type RateLimiter struct {
	mu       sync.Mutex
	rps      int
	tokens   float64
	lastFill time.Time
	now      func() time.Time
}

// NewRateLimiter создаёт лимитер на rps разрешений в секунду.
func NewRateLimiter(rps int) *RateLimiter {
	return &RateLimiter{
		rps:      rps,
		tokens:   float64(rps),
		lastFill: time.Now(),
		now:      time.Now,
	}
}

// Allow возвращает true, если операция укладывается в лимит.
// Метод не блокирует.
func (rl *RateLimiter) Allow() bool {
	rl.mu.Lock()
	defer rl.mu.Unlock()

	now := rl.now()
	// Пополнение: за прошедшее время добавляем rps токенов в секунду,
	// но не превышаем ёмкость бакета.
	elapsed := now.Sub(rl.lastFill)
	if elapsed > 0 {
		rl.tokens += float64(rl.rps) * elapsed.Seconds()
		if rl.tokens > float64(rl.rps) {
			rl.tokens = float64(rl.rps)
		}
		rl.lastFill = now
	}

	if rl.tokens >= 1 {
		rl.tokens--
		return true
	}
	return false
}
```

## Почему это работает

Дробные токены сохраняют остаток между вызовами. Например, при 10 rps
за 150ms поступает 1.5 токена: после одного допуска оставшиеся 0.5 участвуют
в следующем пополнении. Целочисленное округление с `lastFill = now`
теряло бы этот остаток и снижало темп.

Метка времени обновляется после учёта положительного elapsed. Округление
не повторяется на каждом вызове; после долгого простоя запас ограничен rps.
Бакет начинается полным, поэтому допускает стартовый burst до rps запросов.
Это ограничение среднего темпа с запасом, а не квота каждого скользящего окна.

Пополнение, проверка `tokens >= 1` и списание выполняются под одним локом:
два вызывающих не смогут потратить один токен. `Allow` не ждёт будущего
токена, но может кратко ждать мьютекс. Ускорение через atomic не гарантировано
и требует измерения и корректного совместного обновления времени и запаса.

Источник `now` вынесен для тестов и должен двигаться монотонно. rps должен
быть положительным. Время расчёта — O(1), фоновой горутины нет.
Для блокирующего ожидания нужен отдельный Wait(ctx) с отменой.
См. [atomic](/book/atomic), [sync](/book/sync-primitives).
