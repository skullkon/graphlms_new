# Проверка курсов Go — 30 сентября 2026 года

Проверены «Основы Go» (12 глав) и «Конкурентность Go» (10 глав, 32 задачи и 7 тематических разделов). Проверку выполняли три агента с разными задачами. Исправления внесены в материалы и эталоны; версии обоих курсов — `0.7.1`.

## Отчёты

- [Ученик](2026-09-30-student.md): экспертная симуляция чтения 18-летним студентом, который только начал программировать; затем повторное чтение новых разделов. Это не исследование с реальными учащимися.
- [Редактор и фактчекер](2026-09-30-editor.md): технические утверждения, официальные источники Go, условия и разборы задач.
- [Методист](2026-09-30-methodologist.md): последовательность, предпосылки всех задач, недостающие объяснения и внедрённая практика.

Исходные находки в отчётах описывают материалы до исправлений. Текущее состояние обозначено в заключительных разделах отчётов.

## Что изменено

Во всех 22 главах появилась самостоятельная практика с ответом и объяснением. Добавлены полный локальный запуск, первый тест, базовые операторы, пояснения места объявления функций, необходимые знания перед главами конкурентности и рекомендуемый порядок задач. Перед сложными заданиями объяснены время и таймеры, HTTP, рекурсия, BFS, очереди, порядок результатов и остановка пула.

Исправлены технические ошибки и устаревшие утверждения о таймерах, `sync.Cond`, гонках, планировщике, атомиках и отмене. Условия задач согласованы с возможностями API: отмена сообщает о завершении, но не убивает произвольную функцию; приоритет и выдача разрешений сами по себе не доказывают справедливость и строгую квоту фактических стартов.

Исправлены эталоны задач 01, 09, 12, 16, 17, 22 и 30: закрытие Or-Channel по значению единственного входа, синхронное закрытие пустого Merge, перезапуск таймера после сброса пачки, сохранение дробных токенов, интервал между разрешениями после простоя, совместное ожидание одного remote-запроса по ID и согласованный учёт начатых задач при остановке пула. Эталоны и проверки синхронизированы в `site/content/tasks` и `trainer/tasks`; условия CLI также обновлены.

## Проверка

Среда исполнения: локальный Go `1.25.6`, macOS/arm64. Эти результаты не являются подтверждением работы всех примеров в браузерном интерпретаторе.

| Проверка | Результат |
|---|---|
| Все блоки `go play` двух книг, отдельный запуск `go run` | 98 из 98; [результаты](evidence/examples-2026-09-30.json) |
| Все эталоны `site/content/tasks` со скрытыми тестами и `-race -count=1` в изолированных модулях | 32 из 32; [результаты](evidence/tasks-2026-09-30.json) |
| `npm test` в `site/web` | 36 файлов, 159 тестов прошли |
| `content:manifest`, `content:check`, `qa`, `git diff --check` | Версии/история/хеши обновлены, ссылки и 32 комплекта задач проверены, ошибок нет |
| Дополнительная проверка методиста новых ответов | 21 Go-блок в 19 изолированных контекстах; локальный запуск и намеренный FAIL первого теста подтверждены; подробности в отчёте методиста |
| Регрессионные проверки 01, 09, 16 и 17 на исходном и исправленном коде | Исходный код падает, исправленный проходит |

Для 01, 09 и 17 проверки добавлены в тесты задач. Для дробного пополнения 16 дополнительно использована изолированная проверка эталона с подменой часов: при 10 токенах/с и семи шагах по 150 мс исходный код выдавал 7 разрешений, исправленный — 10. Эта проверка не добавлена в скрытые тесты: она использует внутреннее поле эталона и не должна навязывать устройство решения ученика.

Успешный `-race` проверяет только выполненные пути и не доказывает отсутствие всех утечек. У функций `Run func()` остаётся явная граница: возврат `Stop` по таймауту не завершает зависший пользовательский код. У leaky bucket в задаче 17 задан порядок жизненного цикла: дождаться вызовов `Acquire`, затем `Stop`.
