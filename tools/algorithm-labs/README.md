# Алгоритмы и структуры данных: локальные лаборатории

Нужен Go 1.22 или новее. Используется только стандартная библиотека, платных API и внешних зависимостей нет. Распакуйте архив в свою рабочую папку и выполняйте команды из `algorithm-labs`.

```sh
go version
go test ./reference
go test ./exercises -run TestLowerBound
```

`reference` — открытые эталоны и независимые проверки. Их тесты должны пройти. `exercises` — три незаполненные функции: LowerBound (глава 03), Topological (глава 11), MinCoins (глава 13). Тест заготовки ожидаемо падает с сообщением `implement ...`; реализуйте функцию самостоятельно. Команда `go test ./...` до завершения всех трёх упражнений также ожидаемо падает. Это не ошибка установки.

После LowerBound переходите к `go test ./exercises -run TestTopological`, затем к `go test ./exercises -run TestMinCoins`. Законченный комплект упражнений проверяется `go test ./exercises`. Ответы видны бесплатно в reference, но сначала запишите собственное решение.

Остальные главы дают отдельные задания для новых файлов в exercises: поиск, скобки, очередь двух стеков, рекурсия, сортировки, дерево, TopK, BFS, Dijkstra, расписание и DSU. Их критерии и ожидаемые результаты находятся в уроках. Базовый тестовый комплект не оценивает автоматически все самостоятельные расширения и финальный CLI.

## Что проверено в эталонах

13 тестовых функций: граница поиска против линейного просмотра, сортировка против стандартной и сохранение входа, окно против полного перебора маленьких строк, скобки, BST, TopK против сортировки, свойства маршрута BFS, ограничения топологии и циклы, Dijkstra против Bellman–Ford и проверка диапазона, динамика монет против BFS, жадные интервалы против перебора подмножеств, DSU против связности графа.

Случайные испытания используют фиксированный seed и небольшие входы. Они воспроизводимы, но не заменяют доказательство корректности. Эталон — читаемая модель, не библиотека для эксплуатации.

## Договоры моделей

- LowerBound требует отсортированный вход, возвращает len(a) при отсутствии границы.
- LongestUnique считает rune, а не байты или графемы; конверсия []rune требует дополнительной памяти.
- BST не балансируется и хранит уникальные ключи. Высота может быть линейной.
- TopK сохраняет кратность и выдаёт возрастающий результат, исходный вход не меняется.
- Графовые ID — индексы 0..V−1. Направление ребра в Topological: сначала источник, затем получатель.
- Dijkstra допускает неотрицательные int64 веса. Infinity = 2^63−1 обозначает недостижимость; вычисляемые конечные кандидаты должны быть меньше Infinity, иначе ошибка.
- MinCoins допускает положительные номиналы и amount 0..1000000; запас каждой монеты неограничен, −1 означает невозможность.
- Интервалы полуоткрытые [Start,End), Start < End, все имеют одинаковую ценность.
- DSU поддерживает добавление связей, но не удаление и не восстановление маршрута.

Финальный проект из главы 16 реализуйте отдельно: загрузка JSON, валидация, plan/path/top и защита выбора алгоритмов. Эталоны отдельных функций не являются готовым финальным проектом.
