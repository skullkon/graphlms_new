На этом этапе вы добавите декодирование координат местоположения.

### Декодирование широты и долготы из оценки

Алгоритм восстановления координат по сути обратен алгоритму вычисления оценки по широте и долготе.

В упомянутом ранее [репозитории GitHub](https://github.com/codecrafters-io/redis-geocoding-algorithm) объясняется это преобразование. В нём есть:

- Описание алгоритма и псевдокод.
- Примеры кода на нескольких языках.
- Набор местоположений и оценок для проверки.

Вот [ссылка на репозиторий](https://github.com/codecrafters-io/redis-geocoding-algorithm).

### Проверки

Тестирующая система запустит программу так:

```bash
$ ./your_program.sh
```

Она добавит несколько местоположений командой `ZADD`. Используемые оценки корректны и могут быть преобразованы обратно в широту и долготу.

```bash
$ redis-cli
> ZADD location_key 3663832614298053 "Foo"
> ZADD location_key 3876464048901851 "Bar"
> ZADD location_key 3468915414364476 "Baz"
> ZADD location_key 3781709020344510 "Caz"
```

Затем отправит несколько команд `GEOPOS`:

```bash
> GEOPOS location_key Foo
# Expecting [["2.294471561908722", "48.85846255040141"]]
```

Она проверит, что ответ — массив RESP, закодированный так:

```
*1\r\n
*2\r\n
$17\r\n
2.294471561908722\r\n
$17\r\n
48.85846255040141\r\n
```

### Примечания

- Преобразование координат в оценку и обратно происходит с потерями. Поэтому проверка допускает погрешность до шестого знака после запятой относительно исходных значений. Например, для примера выше будут приняты любые из следующих координат:
  - `["2.2944715", "48.8584625"]`;
  - `["2.294472", "48.858463"]`;
  - `["2.294471594", "48.858462987"]`.
