На этом этапе вы отправите список расширений, поддерживаемых вашим клиентом.

### Идентификаторы расширений и рукопожатие

Каждый пир хранит соответствие между именами расширений и идентификаторами. Одному имени расширения у разных пиров могут соответствовать разные идентификаторы, но для конкретного пира идентификатор остаётся постоянным.

Для общения с другими пирами через [расширение метаданных](https://www.bittorrent.org/beps/bep_0009.html#ut_metadata) ваш пир должен знать идентификатор, используемый удалённым пиром для этого расширения. Имя расширения метаданных — `ut_metadata`. Чтобы узнать идентификатор, нужно отправить сообщение [рукопожатия расширений](https://www.bittorrent.org/beps/bep_0010.html#handshake-message) и дождаться соответствующего ответного сообщения пира.

Сообщение рукопожатия расширений содержит такой словарь:

```json
{
  "m": {
    "ut_metadata": 16,
    ... (other extension names and IDs)
  }
}
```

В этом примере `16` — идентификатор расширения метаданных, используемый пиром. Это лишь пример: можно выбрать любое значение идентификатора.

Программа должна отправить сообщение рукопожатия расширений вскоре после получения сообщения битового поля. Общая последовательность:

- Установить TCP-соединение с пиром.
- Отправить сообщение базового рукопожатия.
- Получить сообщение базового рукопожатия.
- Отправить сообщение битового поля (в этом задании можно пропустить).
- Получить сообщение битового поля.
- Если пир поддерживает расширения (судя по зарезервированному биту базового рукопожатия):
  - Отправить сообщение рукопожатия расширений.
  - Получить сообщение рукопожатия расширений.

Обратите внимание: сообщение рукопожатия расширений отправляется только тогда, когда удалённый пир поддерживает расширения, о чём сообщает зарезервированный бит базового рукопожатия. Так сохраняется обратная совместимость с пирами без поддержки расширений.

На этом этапе мы реализуем отправку сообщения рукопожатия расширений. Получение реализуем на следующем этапе.

### Формат рукопожатия расширений

Сообщения расширений следуют стандартному формату сообщений BitTorrent:

- Префикс длины сообщения (4 байта).
- Идентификатор сообщения (1 байт).
  - Для всех сообщений, реализованных расширениями, равен 20.
- Полезная нагрузка (переменный размер).

Структура полезной нагрузки:

- Идентификатор сообщения расширения (1 байт).
  - Для рукопожатия расширений равен 0.
- Словарь bencode (переменный размер).
  - Содержит ключ "m", значением которого является другой словарь.
  - Внутренний словарь сопоставляет имена поддерживаемых расширений соответствующим идентификаторам сообщений.
  - Например, `{"ut_metadata": 1, "ut_pex": 2}` означает, что пир поддерживает расширения "ut_metadata" и "ut_pex" с идентификаторами 1 и 2 соответственно.

Нас интересует имя "ut_metadata", соответствующее [расширению метаданных](https://www.bittorrent.org/beps/bep_0009.html#ut_metadata).

### Тесты

Тестирующая система запустит вашу программу следующим образом:

```
$ ./your_program.sh magnet_handshake <magnet-link>
```

Ожидаемый вывод:

```
Peer ID: 0102030405060708090a0b0c0d0e0f1011121314
```

Вывод совпадает с предыдущим этапом. Дополнительно тестирующая система проверит, что:

- Получено сообщение рукопожатия расширений.
- Оно содержит словарь вида `{"m": {"ut_metadata": <PICK YOUR ID>}}`.
- Идентификатор для `ut_metadata` находится в диапазоне от 1 до 255: он должен представляться 8-битным беззнаковым целым числом, отличным от 0.

### Примечания

- Программа должна отправлять рукопожатие расширений **только если** пир поддерживает расширения.
  - Чтобы это определить, проверьте зарезервированные байты сообщения базового рукопожатия.
- Сообщение рукопожатия расширений описано в [разделе о рукопожатии](https://www.bittorrent.org/beps/bep_0010.html#handshake-message) документации протокола расширений.
