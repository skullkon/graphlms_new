На этом этапе вы расширите встроенную команду `type` для поиска исполняемых файлов с помощью PATH.

### Переменная окружения PATH

Переменная окружения [PATH](https://app.codecrafters.io/concepts/what-is-path) задаёт список каталогов, в которых оболочка должна искать исполняемые программы.

Например, если PATH имеет значение `/dir1:/dir2:/dir3`, оболочка ищет исполняемые файлы сначала в `/dir1`, затем в `/dir2` и наконец в `/dir3`, именно в таком порядке.

### Поиск исполняемых файлов

Когда `type` получает имя команды, оболочка должна выполнить следующие шаги:
1. Проверить, является ли команда встроенной (например, `exit` или `echo`). Если да, сообщить об этом (`<command> is a shell builtin`) и остановиться.
2. Если команда не встроенная, пройти по всем каталогам в PATH. Для каждого каталога:
    1. Проверить, существует ли файл с именем команды.
    2. Проверить, имеет ли файл **разрешение на выполнение**.
    3. Если файл существует и имеет разрешение на выполнение, вывести `<command> is <full_path>` и остановиться.
    4. Если файл существует, но **не имеет разрешения на выполнение**, пропустить его и перейти к следующему каталогу.
3. Если исполняемый файл не найден ни в одном каталоге, вывести `<command>: not found`.

Например:

```bash
$ type grep
grep is /usr/bin/grep
$ type invalid_command
invalid_command: not found
$ type echo
echo is a shell builtin
```

### Проверки

Тестирующая система запустит вашу программу с собственным `PATH` следующим образом:

```bash
PATH="/usr/bin:/usr/local/bin:$PATH" ./your_program.sh
```

Затем система отправит оболочке последовательность команд `type`:

```bash
$ type ls
ls is /usr/bin/ls
$ type valid_command
valid_command is /usr/local/bin/valid_command
$ type invalid_command
invalid_command: not found
$
```

Тестирующая система проверит, что команда `type` правильно определяет исполняемые файлы в PATH:
- Исполняемые файлы из PATH отображаются с полным путём (`<command> is <full_path>`).
- Файлы без разрешения на выполнение пропускаются.
- Для несуществующих команд выводится сообщение `<command>: not found`.

### Примечания




- Можно использовать [exec.LookPath](https://pkg.go.dev/os/exec#LookPath) или самостоятельно реализовать обход PATH.






- PATH может включать каталоги, отсутствующие на диске, поэтому ваш код должен корректно обрабатывать такие случаи.
- При разборе переменной окружения PATH помните, что разделитель (обычно `:` или `;`) может зависеть от операционной системы. Чтобы правильно разделить каталоги, используйте независимые от ОС средства работы с путями вашего языка (например, `os.pathsep` в Python, `File.pathSeparator` в Java или `path.delimiter` в Node.js).
