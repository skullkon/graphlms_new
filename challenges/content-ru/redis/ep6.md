На этом этапе вы обеспечите запись в AOF только команд, изменяющих данные.

### Отбор команд, изменяющих данные

Команды, которые не меняют данные, например `PING`, `GET` и `ECHO`, не должны попадать в AOF, поскольку они не изменяют состояние.

Если сервер получает команды чтения и записи вперемешку, файл AOF должен содержать только команды записи в порядке поступления.

Например, если клиент отправляет:

```bash
$ redis-cli SET foo 1
$ redis-cli GET foo
$ redis-cli PING
$ redis-cli ECHO hello
$ redis-cli SET bar 2
```

Файл AOF должен содержать только две команды `SET`:

```
*3\r\n
$3\r\n
SET\r\n
$3\r\n
foo\r\n
$1\r\n
1\r\n
*3\r\n
$3\r\n
SET\r\n
$3\r\n
bar\r\n
$1\r\n
2\r\n
```

*(Для удобства чтения последовательности `\r\n` выше показаны на отдельных строках. В настоящем файле каждая команда — непрерывная последовательность байтов.)*

Никаких следов `GET`, `PING` или `ECHO` в файле быть не должно.

### Тесты

Тестирующая программа запустит вашу программу так:

```bash
$ ./your_program.sh --dir <dir> --appendonly yes --appenddirname <append_dir_name> --appendfilename <append_file_name> --appendfsync always
```

Она отправит смесь изменяющих и неизменяющих данные команд, в том числе `PING`, `GET`, `ECHO` и `CONFIG GET`, чередуя их как минимум с одной командой записи.

Будет проверено, что:

- Файл AOF содержит только команды записи в правильном порядке.
- Байты команд, не меняющих данные, отсутствуют в файле.
- Каждая записанная команда имеет корректный формат RESP.

### Примечания

- Если у вас уже есть логика различения команд записи и чтения, например для репликации, её можно использовать здесь.
- Для определения файла записи необходимо прочитать манифест. Тест использует нестандартное имя файла.
- На этом этапе не нужно поддерживать `--appendfsync everysec`.
