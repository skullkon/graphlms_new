На этом этапе вы расширите встроенную команду `cd` для обработки относительных путей.

### Встроенная команда `cd`: напоминание

Напомним, что `cd` может принимать аргументы нескольких типов:

- Абсолютные пути, например `/usr/local/bin`. (Обработаны на предыдущих этапах.)
- Относительные пути, например `./`, `../`, `./dir`.
- Символ `~`.

На этом этапе вы обработаете второй тип аргументов.

### Относительные пути

Относительный путь задаёт расположение относительно текущего рабочего каталога, а не корня файловой системы.

Оболочка должна корректно интерпретировать следующие компоненты относительного пути и переходить по ним:

- `./` (текущий каталог): ссылается на сам текущий рабочий каталог.
- `../` (родительский каталог): ссылается на каталог непосредственно над текущим рабочим каталогом в иерархии файловой системы.
- Подкаталоги: пути вида `./dirname` или `dirname` считаются относительными к текущему каталогу.

Несколько примеров:
```bash
$ pwd
/usr
$ cd ./local/bin    # Go to "local/bin" inside current directory (/usr)
$ pwd
/usr/local/bin
$ cd ../../         # Go up two levels
$ pwd
/usr
$ cd local          # "local" is shorthand for "./local"
$ pwd
/usr/local
```

### Проверки

Тестирующая система запустит вашу программу следующим образом:

```bash
./your_program.sh
```

Затем система отправит оболочке последовательность команд `cd`:

```bash
$ cd /usr
$ pwd
/usr
$ cd ./local/bin
$ pwd
/usr/local/bin
$ cd ../../
$ pwd
/usr
$
```

Тестирующая система проверит, что:
- Корректные относительные пути правильно меняют каталог.
- Для некорректных относительных путей выводится сообщение `cd: <directory>: No such file or directory`.
- При неудачном выполнении `cd` каталог остаётся прежним.

### Примечания

- Фактические имена каталогов будут случайными, поэтому нельзя жёстко задать ожидаемый вывод.
