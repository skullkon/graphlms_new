## Одинаковая модель, разные результаты

В одном окружении агент видит только запрос «добавь завершение задачи». В другом ему доступны спецификация, исходники, команда проверки и статус предыдущей сессии. Во втором случае меньше причин угадывать. Изменили условия работы, хотя модель могла остаться прежней.

**Харнесс** — программное окружение, которое организует работу модели: передаёт контекст, предоставляет инструменты, исполняет вызовы, возвращает результаты и управляет продолжением или остановкой. В разговоре «мой харнесс» нередко означает также настроенный рабочий процесс вокруг готового агента. В курсе мы различаем эти уровни.

Claude Code и Codex уже предоставляют рантайм агента. Вы можете настроить его для проекта, не создавая собственный цикл вызовов модели. Инструкции, скилл и скрипт проверок будут частью этой настройки. Сам по себе каталог Markdown-файлов не становится исполняемым рантаймом.

## Цикл работы

```text
Человек задаёт цель
  → рантайм собирает доступный контекст
  → модель предлагает действие
  → окружение проверяет права и исполняет инструмент
  → результат возвращается модели
  → цикл продолжается или останавливается
  → человек получает изменение и доказательства проверки.
```

Модель может предложить действие, которого нет среди инструментов, или получить ошибку выполнения. Следующий шаг должен учитывать наблюдаемый результат. Без ограничения времени, числа попыток или стоимости такой цикл может повторяться без полезного продвижения.

## Что должен обеспечивать рабочий процесс

| Задача | Механизм в учебном проекте |
|---|---|
| Понять цель | SPEC.md с примерами |
| Найти текущее состояние | STATUS.md и история Git |
| Выполнить действия | Файловые инструменты и запуск Python |
| Проверить результат | Тесты, ручной сценарий и diff |
| Ограничить действия | Права среды и подтверждение внешних операций |
| Продолжить в новой сессии | Записанный статус и следующая задача |
| Остановить бесполезные повторы | Лимит попыток и разбор причины |

Инструкция «не удаляй данные» сообщает намерение. Тест обнаруживает конкретное нарушение. Ограничение доступа мешает инструменту работать за пределами разрешённой области. У этих механизмов разные функции; один не заменяет остальные.

## Откуда взялась потребность

В инженерном материале [Anthropic о длительной работе агентов](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) обсуждается продолжение задач между сессиями: состояние приходится передавать явно. Для нашего курса это повод сохранять маленькие законченные шаги и следующую задачу. Это учебная адаптация, а не обещание повторить результаты эксперимента на любом проекте.

Для долгой автономной разработки могут понадобиться очередь задач, журнал вызовов, восстановление после сбоя и независимая оценка. Новичку сначала нужно проверить, что короткий цикл с человеком работает. Автоматизация плохо понятого процесса ускоряет повторение тех же ошибок.

## Самостоятельное задание

Нарисуйте цикл своего агента на бумаге. Отметьте, откуда приходят требования, кто исполняет команды, где проверяется результат и какое условие останавливает работу. Подпишите один пример того, что обеспечивает инструкция, и один пример технического ограничения.

## Критерии и разбор

На схеме есть результаты инструментов и обратная связь, а не только стрелка от запроса к коду. Вы объясняете, почему подключение MCP расширяет инструменты, но не решает автоматически проблему памяти, проверки и остановки.
