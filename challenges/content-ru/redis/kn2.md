На этом этапе вы добавите воспроизведение файлов AOF с несколькими командами.

### Воспроизведение нескольких команд

Файл AOF обычно содержит много команд. Сервер должен разобрать его как последовательность команд RESP и воспроизвести каждую по порядку, как если бы их отправлял подключённый клиент.

RESP сам задаёт границы сообщений: каждая команда начинается с `*<n>\r\n`, указывающего её длину. Поэтому команды можно читать одну за другой до конца файла. Каждую разобранную команду следует применить к состоянию сервера, прежде чем переходить к следующей.

После воспроизведения всех команд база данных должна отражать совокупный результат всех записей в файле.

### Тесты

Тестирующая программа создаст каталог `<dir>/<append_dir_name>`, содержащий:

- Файл AOF `<random_file_name>.1.incr.aof` с несколькими командами RESP, например несколькими `SET` для разных ключей.
- Манифест `<append_file_name>.manifest`, указывающий на этот файл AOF:

```
file <random_file_name>.1.incr.aof seq 1 type i
```

Она запустит вашу программу так:

```bash
$ ./your_program.sh --dir <dir> --appendonly yes --appenddirname <append_dir_name> --appendfilename <append_file_name>
```

После запуска отправит несколько команд `GET`, чтобы проверить восстановление каждого ключа:

```bash
$ redis-cli GET <key1>
$ redis-cli GET <key2>
...
```

Будет проверено, что:

- Каждый `GET` возвращает значение соответствующей команды из файла AOF.
- Воспроизведены все команды AOF, а не только первая.

### Примечания

- Если реализация уже читает файл в цикле до EOF, этот этап может пройти без изменений.
- Читать и воспроизводить нужно файл из манифеста, а не файл с жёстко заданным именем `<append_file_name>.1.incr.aof`.
- RESP сам задаёт границы сообщений, поэтому разделители между командами не нужны. Продолжайте разбор, пока не закончатся байты.
