# Агентская симуляция учебного цикла

Это техническая и педагогическая проверка агентом по исходному коду, сценариям и тестам. Реальных учащихся в ней не было. Отчёт не подтверждает понятность материалов новичкам, улучшение результатов обучения или пригодность расписания для конкретного человека. Человеческий пилот остаётся отдельной задачей.

Проверены `LearningCycle`, `ReviewPractice`, определения 16 сценариев и функции проверки попыток и расписания. Чужие файлы в ходе проверки не изменялись. После исправлений выполнена повторная проверка кода и четырёх тестовых наборов. Итоговый прогон: 20 из 20 тестов прошли; обе найденные проблемы закрыты в проверенном состоянии.

## Пройденные маршруты

| Проверка | Наблюдение | Значение для обучения |
|---|---|---|
| Пустая попытка → выбор ответа | Кнопка проверки недоступна без объяснения длиной 40 символов и допустимого выбора | Разбор не открывается одним случайным нажатием |
| Неверный выбор с объяснением → проверка | Показывается причина ошибки именно этого варианта и разбор состояния | Обратная связь объясняет механизм, а не только сообщает балл |
| Верный выбор → изменение ответа | Сбрасываются `checked` и `passed`, требуется новая проверка | Старый успех не переносится на изменённый ответ |
| Подсказки → сохранение → повторное открытие | Подсказки выдаются последовательно, их число сохраняется | Видно, какая поддержка была использована; она не объявляется самостоятельным решением |
| Основной разбор → новое условие | Новый ответ хранится отдельно; его разбор скрыт до попытки | Перенос требует отдельного объяснения, исходный выбор его не заменяет |
| Успешный выбор сценария → прогресс курса | Компонент не пишет ключ контрольного вопроса главы | Проверка одного варианта не объявляет завершение всей главы |
| Нет завершённых сценариев → повторение | Показан путь к первой задаче, список результатов не выдумывается | Нет фиктивной истории обучения |
| Завершённый сценарий → повторение | Используется задача на изменённое условие, ответ пишется до разбора | Требуется извлечение знания, а не чтение готового объяснения с самого начала |
| Разбор повторения → самооценка | Выбор «есть пробел» / «объяснил самостоятельно» задаёт интервал | Система не выдаёт эту оценку за экспертное измерение понимания |
| Сохранённое повторение → следующий запуск | Ответ после оценки очищается, разбор снова скрыт | Старый текст не становится новой попыткой автоматически |
| Повреждённое расписание | `ReviewPractice` блокирует работу с форматом и предлагает экспорт исходных данных | Не теряются прошлые учебные записи |

## Проверка смысла задач

Агент сопоставил причинные связи в нескольких характерных сценариях:

- В главе 03 повтор отмены должен менять счётчик только при первом переходе активного участия; два клиентских запроса не означают две отменённые записи.
- В главе 06 запоздалое заполнение кэша требует протокола версий либо честного ослабления требования свежести. TTL не представлен как немедленная согласованность.
- В главе 09 ключ внешнего провайдера действует только в пределах заявленного срока. Новое условие без ключей и проверки статуса не получает обещания единственного внешнего эффекта.
- В главе 10 удалённую историю нельзя восстановить настройкой WebSocket. Разбор отделяет непрерывное продолжение от загрузки доступного состояния.
- В главе 11 три уведомления не доказывают три разных результата. Публикация привязана к множеству обязательных качеств и версии исходника.
- В главе 12 ограничения аккаунта и общего пула защищают ресурс от обхода одного IP-лимита; проверка личности не приравнивается к неограниченной квоте.

Эти проверки подтверждают связность конкретных объяснений. Они не измеряют, сможет ли школьник самостоятельно сформулировать тот же механизм без вариантов ответа.

## Найденные и исправленные проблемы

### P2: повреждённая попытка LearningCycle могла быть перезаписана — исправлено

В исходной версии неверный JSON вызывал предупреждение, но первое редактирование или открытие подсказки заменяло исходную запись. Поздняя версия из другого окна также могла быть перезаписана без сравнения.

Повторная проверка подтвердила блокировку повреждённой записи и экспорт исходных данных. Новая попытка создаётся только явной командой восстановления. Перед сохранением текущая запись сравнивается с прочитанной: при конфликте локальный черновик остаётся на экране, сохранённая версия не перезаписывается, её загрузка требует отдельного действия. Отдельный ответ на изменённое условие также проверяет конфликт перед записью.

Два DOM-теста подтверждают сохранность повреждённого JSON до явного восстановления и отсутствие перезаписи при конфликте с другим окном. Исправление проверено чтением кода и успешным повторным прогоном.

### P2: дата первого ошибочного ответа сдвигала повторение в прошлое — исправлено

Ранее `checkCycle` сохранял время самой первой попытки. Если учащийся исправлял неверный ответ через несколько дней, первый срок повторения отсчитывался от старой даты.

Теперь каждая проверка записывает переданное текущее время через `attemptedAt: now`. После успешного исправления расписание использует дату актуальной проверенной попытки. Регрессионный тест с первой попыткой в момент 100 и повторной в момент 200 проходит; ожидание даты второй попытки сохранено.

Обе проблемы передавались основному агенту сразу после обнаружения. В рамках агентского пилота чужие компоненты и тесты не изменялись.

## Доказательства и ограничения

Команда из `site/web`:

```sh
npx vitest run lib/system-design/learningCycle.test.ts lib/system-design/reviews.test.ts components/system-design/LearningCycle.test.tsx components/system-design/ReviewPractice.test.tsx
```

В итоговом прогоне 28 сентября 2026 года в 23:36 прошли все 20 тестов: 6 проверок учебного цикла, 3 расписания, 8 DOM-проверок `LearningCycle` и 3 DOM-проверки `ReviewPractice`. Ранний сбой даты попытки устранён; результат 17 из 18 относится к состоянию до исправлений и не является итогом пилота. DOM-тесты выполняются в jsdom: они проверяют доступность кнопок, открытие разбора, сохранение и смену главы; они не заменяют проверку в браузере с клавиатурой и скринридером.

Для человеческого пилота остаётся проверить: понятен ли запрос на причинное объяснение; не раскрывают ли подсказки ответ раньше полезной попытки; может ли учащийся решить изменённое условие без вариантов; соответствует ли самооценка его устному объяснению; достаточно ли заметны различия между проверенным выбором, пройденной главой и освоенной темой. Результаты этих наблюдений пока не собраны.
