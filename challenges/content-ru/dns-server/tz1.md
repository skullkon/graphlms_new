Все данные в протоколе DNS передаются в едином формате, называемом «сообщением». Каждое сообщение состоит из 5 разделов: заголовок, вопросы, ответы, полномочия и дополнительный раздел.

На этом этапе мы сосредоточимся на заголовке. Остальные разделы рассмотрим на следующих этапах.

### Структура заголовка

Заголовок DNS-сообщения содержит следующие поля (в таблице также приведены значения, которые тестирующая система ожидает на этом этапе):

| Поле | Размер | Описание |
| --------------------------------- | ------- | -------------------------------------------------------------------------------------------------------------------- |
| Идентификатор пакета (ID) | 16 бит | Случайный идентификатор, присваиваемый пакету запроса. Пакет ответа должен содержать тот же идентификатор. <br />**Ожидаемое значение**: 1234. |
| Признак запроса/ответа (QR) | 1 бит | 1 для пакета ответа, 0 для пакета запроса. <br />**Ожидаемое значение**: 1. |
| Код операции (OPCODE) | 4 бита | Задаёт вид запроса в сообщении. <br />**Ожидаемое значение**: 0. |
| Авторитетный ответ (AA) | 1 бит | 1, если отвечающий сервер «владеет» запрошенным доменом, то есть является авторитетным для него. <br />**Ожидаемое значение**: 0. |
| Усечение (TC) | 1 бит | 1, если сообщение превышает 512 байт.<br />**Ожидаемое значение**: 0. |
| Запрошена рекурсия (RD) | 1 бит | Отправитель устанавливает 1, если сервер должен рекурсивно разрешить запрос, иначе 0. <br />**Ожидаемое значение**: 0. |
| Рекурсия доступна (RA) | 1 бит | Сервер устанавливает 1, чтобы сообщить о доступности рекурсии. <br />**Ожидаемое значение**: 0. |
| Зарезервировано (Z) | 3 бита | Используется запросами DNSSEC. Изначально было зарезервировано для будущего использования. <br />**Ожидаемое значение**: 0. |
| Код ответа (RCODE) | 4 бита | Код, обозначающий состояние ответа. <br />**Ожидаемое значение**: 0 (нет ошибки). |
| Количество вопросов (QDCOUNT) | 16 бит | Количество вопросов в разделе вопросов. <br />**Ожидаемое значение**: 0. |
| Количество записей ответов (ANCOUNT) | 16 бит | Количество записей в разделе ответов. <br />**Ожидаемое значение**: 0. |
| Количество записей полномочий (NSCOUNT) | 16 бит | Количество записей в разделе полномочий. <br />**Ожидаемое значение**: 0. |
| Количество дополнительных записей (ARCOUNT) | 16 бит | Количество записей в дополнительном разделе. <br />**Ожидаемое значение**: 0. |

Длина заголовка всегда составляет 12 байт. Целые числа кодируются с порядком байтов big-endian.

Подробнее о полном формате DNS-пакета можно прочитать в [Википедии](https://en.wikipedia.org/wiki/Domain_Name_System#DNS_message_format) или в [RFC 1035](https://tools.ietf.org/html/rfc1035#section-4.1). По [этой ссылке](https://github.com/EmilHernvall/dnsguide/blob/b52da3b32b27c81e5c6729ac14fe01fef8b1b593/chapter1.md) находится хорошее руководство, подробно разбирающее формат DNS-пакета.

### Тесты

Тестирующая система запустит вашу программу следующим образом:

```bash
$ ./your_program.sh
```

Затем она отправит на порт 2053 UDP-пакет с DNS-запросом. Ваша программа должна отправить ответный DNS-пакет с описанным выше заголовком.

Рекомендуем создать в коде внутреннюю структуру для «DNS-сообщения»: на следующих этапах мы будем её развивать.

Примечание: в начале тестирования каждого этапа тестирующая система отправляет дополнительный пакет. Его можно игнорировать.
