На этом этапе вы добавите отслеживание ещё не существующих ключей.

### Отслеживание отсутствующих ключей

До сих пор вы отслеживали только ключи со значениями. Но `WATCH` работает и для ключей, отсутствующих в момент вызова. Если другой клиент создаст такой ключ до `EXEC`, транзакция также должна отмениться.

```bash
# Client A
> WATCH foo
OK

# Client B
> SET foo 300
OK

# Client A
> MULTI
OK
> SET bar 500
QUEUED
> EXEC
*-1\r\n                # transaction aborted, foo was created after WATCH
```

Ключа не было, когда клиент A начал его отслеживать, но клиент B создал его до `EXEC`. Это считается изменением.

### Тесты

Тестирующая программа запустит вашу программу так:

```bash
$ ./your_program.sh
```

Затем создаст двух клиентов. Первый начнёт отслеживать отсутствующий ключ:

```bash
# Client 1
> WATCH foo
OK
```

Второй создаст отслеживаемый ключ:

```bash
# Client 2
> SET foo 200
OK
```

Первый начнёт транзакцию и попытается её выполнить:

```bash
# Client 1
> MULTI
OK
> SET foo 300
QUEUED
> EXEC
*-1\r\n                # transaction aborted
> GET foo
"200"                  # unchanged, transaction had no effect
```

Будет проверено, что:

- `EXEC` возвращает нулевой массив RESP (`*-1\r\n`), если другой клиент создал отслеживаемый ключ.
- Команды отменённой транзакции не оказали эффекта.

### Примечания

- Если реализация уже помечает отслеживаемые ключи при любой команде записи, этап может пройти без изменений.
- Главное: переход от отсутствующего ключа к существующему тоже считается изменением. У ключа не обязано быть предыдущее значение, чтобы запись в него учитывалась.
